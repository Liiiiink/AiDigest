  1. EMBRACE：五个 AI 编码工具的内置浏览器被成套攻破，微软和 OpenAI 还没修 — 10 月 29 日公开，覆盖 Cursor、GitHub Copilot、OpenAI Codex、VS Code 和 Claude Desktop。 实战

    根因是同一个：这些工具内置的浏览器由 AI 驱动而不是人在点，厂商为了让 AI 能预览项目、读取标签页内容，普遍放松了独立浏览器该有的沙箱边界，于是内置浏览器继承了宿主级别的文件访问权限。研究者 Gal Weizman 给这类问题起名 EMBRACE（EMbedded BRowser, trusted like a real one）。

    三种后果分开看：Cursor 是代码执行——恶意页面滥用内置浏览器与 AI 助手之间的桥接，把隐藏指令注入命令编排框，实测中助手被骗着执行命令弹出了计算器；GitHub Copilot 是地址栏欺骗——地址栏和 agent 都显示 github.com/login，实际渲染的是攻击者的页面；Codex、VS Code、Claude Desktop 是一个本地文件读全盘——利用 macOS 在 Finder 打开过的目录里留下的隐藏索引文件来测绘磁盘。

    补丁状态要记清楚：Cursor 10 月 1 日已静默修复，Copilot 的欺骗修复在 build 1.1.29；截至 10 月 29 日微软和 OpenAI 都还没发修复。利用前提是开发者点了助手生成的指向本地恶意 HTML 的链接——所以今天的动作就是：别点 agent 丢给你的本地 HTML 预览链接。

    作用范围只限桌面应用的内置浏览器，终端里的 Claude Code 没有内置浏览器，不在测试范围内。另有一个「信任提示绕过」问题：既然不点 Trust 根本用不了这些工具，那个保护在实践中等于不存在。

  2. GitHub Copilot code review 加了 Max 档：多家模型各自独审，再由一个聚合 agent 合成一份意见 — 10 月 28 日进 public preview，Lite / Balanced 之上多了第三档。 新发布

    Max 的做法是跑多个互相独立的 review agent，分别用不同厂商的模型，再用一个聚合 agent 把各家的发现对账合并成一份评审。代价明说了：更慢、更费 AI credits。

今日术语

  • 嵌入式浏览器（Embedded Browser）：桌面应用内部自带的那个浏览器内核（比如 VS Code 里的网页预览窗）；它跑在应用进程里，权限往往跟着宿主走，不像独立浏览器那样被沙箱关着——今天 EMBRACE 整件事的根源就在这。
  • 地址栏欺骗（Address Bar Spoofing）：页面内容是攻击者的，但地址栏显示的却是正经域名；因为用户判断真假几乎只看地址栏，这招专门用来钓登录凭据。
  • 模型路由（Model Routing）：一个中间层按任务难度自动替你挑模型，简单活走便宜小模型、难活走贵的大模型，你不用手动选——GitHub Copilot Fusion 就是干这个的，代价是厂商通常不告诉你这次到底用了谁。
  • 供应链攻击（Supply Chain Attack）：不直接打你，而是打你依赖的那个包／镜像／构建流水线，等你照常 pip install 的时候把恶意代码送进你的机器——LiteLLM v1.107.0 就是这么进了近 5 万次下载的环境。
