  1. AWS 开源 Kiro Crew:3 个人做的副业,半年 4 万内部开发者,现已 Apache 2.0 — 一个长运行、跨会话的多 Agent 工作台。核心能力:①跨会话记忆——定期合并会话,把反复出现的问题和技术栈偏好存为语义记忆;②多 Agent 并行——一个 Agent 可以每 5 分钟检查 CI 构建、分析错误、自动修复并重提交;③Issue Radar——连接代码仓库,自动判断哪些 issue 可操作并启动新 Agent 会话;④可复用技能——检测到重复工作模式后推荐生成 Skill,Agent 间共享;⑤记忆治理——可查询记忆来源、编辑或删除错误内容,防止「一次幻觉变成长期错误」。设计哲学是从「vibe coding」转向「规范驱动开发」——Spec 是开发者与 Agent 之间的契约。
    为什么值得关注:和上周 Uber 的 Agent 平台是同一条路的不同走法——Uber 做的是「极致省 token」,Kiro Crew 做的是「让 Agent 能长时间自主运行」。第 ⑤ 条记忆治理尤其关键:能编辑和删除 Agent 的记忆,是让「长期运行」不变成「长期积累错误」的前提。
    工具AWS / InfoQ2026-09-04
  2. GitHub Copilot 支持多 Agent 并行:同时跑多个 Agent,各干各的 — 新功能允许在 Copilot App 中同时启动多个 Agent 并行工作,每个 Agent 独立处理不同任务。对新手友好——不需要理解 Agent 内部机制,只需描述要做什么。配合 GitHub 同日发布的另一篇成本优化文章:解释了为什么「更短的输出」有时反而更贵(因为 Agent 要反复重试),以及如何通过减少「跨任务浪费」来降本。

  3. Mistral 发布 Agentic Search:把 RAG 从「一次检索」升级为「多步翻阅」 — 给模型 5 个类文件系统工具:search(找文档)、open(打开)、navigate(跳到某页/某节)、read(读内容)、grep(文档内搜索)。模型不再从固定 chunk 里回答,而是反复搜索→打开→翻阅→再搜索。FinanceBench 上准确率从 26.7% 跳到 86%(+59.3pp),导航工具同时降低 token 消耗 33.7% 和 p90 延迟 39.6%。结论很硬:检索质量随模型能力提升而提升,不再被 chunking 策略封顶。跨模型验证(Mistral Medium 3.5 和 GLM-5.2 都有效),说明方法是模型无关的。通过 Mistral Search Toolkit 开源,Studio 和 Vibe 可直接用。
    为什么值得关注:这是对 RAG 范式一次干净的升级——把「检索」从一步变成 Agent 循环,且用文件系统语义(open/navigate/read)做抽象。那个「从 26.7% 到 86%」的跳跃说明:很多 RAG 系统的问题不是模型不够聪明,是检索层没有给它翻资料的机会。

今日新词

  • ARC-AGI-3:衡量 AI 通用推理能力的基准测试,题目是视觉逻辑谜题(看几张图、找出规律、补全下一张)。不像数学考试那样可以靠刷题过关——它测的是「能不能从很少的例子中抽象出规则」。今天 Astra 拿了 99.9%,下一个最好的模型只有 30.2%,说明这个基准可能已经被「做穿」了。
  • MoVA(Mixture-of-Value Attention):K2 Horizon 今天引入的新机制。常规 MoE 只在 Transformer 的 FFN 层做「专家分工」,MoVA 把这种稀疏化也用到 Attention 层——相当于不只让不同专家处理不同的知识,还让不同专家处理不同的「注意模式」。结果是 36B 总参数、每 token 只需激活 ~4B,就接近 32B 稠密模型的性能。
