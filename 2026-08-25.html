HN:恶意模型可以纯靠「吐 token」打穿推理引擎,拿下 GPU 宿主机 — 一个很少被认真讨论的威胁模型:攻击面不是模型说了什么,而是谁在解析它说的话。链路是——模型控制自己的输出 token,而 vLLM / SGLang 这类推理引擎要对这些 token 做大量解析(工具调用、推理块、聊天模板),解析器有 bug 就能拿到宿主机上的任意代码执行。目标价值极高:GPU 宿主机上有前沿算力、模型权重本身,以及数据中心内网的特权访问。真实案例:CVE-2025-9141——vLLM 给 Qwen3 Coder 写的 XML 工具调用解析器,「几乎把每一个工具调用参数都传给了 eval()」。更值得记的是那段过程:Gemini 的自动化分析把引入这个漏洞的 PR 标成了严重漏洞,而 vLLM 的首席维护者强制合并了它。为什么面这么大:vLLM 支持 200+ 种模型架构,约 35 个 Jinja 聊天模板,解析复杂度和 bug 面成正比。文中还展示了一个已证实的解析 bug:模型吐一个 <mm:think>,被误当成推理块的开始而不是字面文本。持久化那段最阴:一旦发现可用的利用串,可以把它存进文件或 URL,变成「持久化提示注入」——Agent 只要做一次「列一下目录」这种日常动作就会被触发。防御建议:把 GPU 宿主机和 token 解析器放在不同机器上,让解析器被打穿也够不到 GPU;以及收紧 GPU 宿主机的权限,把它吐出来的一切数据都当不可信输入。另外提醒了一条:让 LLM 去写推理引擎的 C++/CUDA 组件,有埋越界访问后门的风险。
    为什么值得关注:如果你在自建推理服务,今晚就能做一件事——去看一眼你的工具调用解析器和聊天模板里有没有 eval / exec / 动态模板求值。这篇最反直觉的一点是:「让模型跑在自己机器上更安全」这个直觉在这里是反的——你把解析器和权重放在了同一台机器上。

Lobste.rs:把可执行文件做成 SQLite 数据库——chmod +x 一个 .db 就能跑 — 一个疯狂但论证扎实的实验:用 SQLite 取代 ELF 当 Linux 原生可执行格式,项目叫 SELF(Structured Executable & Linkable Format)。核心洞察:ELF 本来就是个数据库,只是把数据库原语全部手搓了一遍——.strtab 是字符串驻留,.gnu.hash 是索引,section header table 是 sqlite_schema,而 strip 就是 DELETE + VACUUM。怎么跑起来:SQLite 在字节偏移 68 处预留了 4 字节 application_id,SELF 往里盖个 "SELF" 戳,再用 Linux 的 binfmt_misc 认这个 magic、转交给一个链接了 libsqlite3 的小 C 程序 self-exec——它干的就是 ld.so 的活:映射段、做重定位、跳到入口。动态链接做了两版原型,其中一版是从零写的动态链接器 self-ld,重定位全部用 SQL 解;self closure 能把一个二进制和它所有传递依赖打进一个库,于是 ldd 变成一次 JOIN,soname 歧义靠外键消掉。数字比想象中好看:strip 过的 coreutils,SELF 1,794,048 B vs ELF 1,768,632 B——差不到 1%;启动有约 5ms 固定开销(SQLite 初始化)。最有说服力的是规模化那组:把系统 PATH 上全部 723 个可执行文件(1123 个对象、346,386 个符号、3808 条依赖边)打进一个数据库,占 611.9 MiB,而原来那堆 ELF 是 644.4 MiB——整个 userland 塞成一个 SQLite 文件反而更小;作为对照,如果每个二进制都带自己的私有闭包(AppImage 那种做法),同样 723 个程序要吃 5.53 GiB。
    为什么值得关注:去重不是优化出来的,是从 schema 里自然长出来的——这是全文最值得带走的一句。就算你永远不会用 SELF,那套「先问这个格式在手搓什么数据库原语」的拆法,对任何自定义二进制格式、缓存格式、包格式都成立。

Firefox 要正式发布 JPEG XL 了——因为 Google 用 Rust 重写了解码器 — 一个关于「安全性怎么解锁一项技术」的干净案例。Firefox 从 2021 年就有 flag 后面的实验性 JPEG XL 支持,但一直不敢开——原版解码器是 10 万行多线程 C++,攻击面太大。Mozilla 的做法是直接向 Google Research 的 JPEG XL 团队下战书:用 Rust 写一个安全、高性能、体积小、兼容的解码器出来。Google 交出了 jxl-rs,现在成了 Firefox 这套支持的内核。顺带拿到的好处:Rust 版支持渐进式渲染(边下边显)——Safari 2023 年那版恰恰缺这个。格式定位很清楚:JPEG XL 强在无损压缩和对存量 JPEG 的无损再压缩(一张无损狐狸图 JPEG XL 1.45 MB vs AVIF 1.76 MB),而网页质量的有损照片 AVIF 一般更小。Chrome 同期也发了 intent to ship,加上 Safari 已有的部分支持,年内有望三家齐活。

  1. 「控制」与「复杂性」的张力:你的团队正在用哪一套,以及它什么时候会失效 — Fred Hebert 的一篇,把系统设计里两种根本对立的取向摆出来。①分析式分解 / 控制:把系统拆成部件来理解和控制,「整体可以从部件推知」——在可预测、变化范围有界的机械系统上很好用。②复杂性 / 涌现:高度互联的系统会变得「要么无法表征,要么无法预测,要么无法控制」,它们是被影响的而不是被控制的,只能迭代适应。最常见的失败模式:系统从简单长成一团相互依赖之后,进一步的干预开始边际递减,而团队的本能反应是「加倍下注」——做更多分析、更多拆解、更灵活的自动化;结果不是消除故障,而是换了个故障形态:事故变少了,但每次更大。四组对照极其实用:代码评审——控制视角把它当抓 bug 的门禁和问责工具,涌现视角把它当跨团队建立认知和反馈的场所;如果组织按前者设立、实践者却偷偷按后者在用,那么改动这个"控制机制"的时候,你会连带砍掉那些看不见的适应。安全——控制是「设计掉危险、阻止导致失败的行为」,涌现是「理解人怎么弥合缺口、怎么从问题中恢复」,即研究工作是怎么成功的,而不只是怎么失败的。SLO——控制视角下它是确保各团队管好可靠性的强制工具,涌现视角下真正的价值来自团队坐下来讨论「多可靠算可以接受」的那个过程,对话比指标重要。事故响应——控制靠 runbook、流程和快速定位防复发,涌现要培养临场发挥的能力,因为「意外本来就需要即兴」。LLM 那段是落点:作者警告当下由 LLM 驱动的组织变革正在重复同样的错误——用自动化门禁取代代码评审却不问这项实践承担了哪些涌现性角色;把工作切成 spec-to-code 流水线却不考虑「值得学习的信息该怎么跨越这些边界」。他那句总结值得贴墙上:提高可预测性的自动化,必然也会移除掉那些对适应有用的不可预测性。

今日新词

  • 负向专长(Negative Expertise):今天最值得记的一个词。指的不是「会做什么」,而是「能看出什么是错的、并且敢拒绝」。研究里那批削弱或忽略 AI 建议的开发者表现最好,靠的就是这个。它的养成方式有点反效率:必须经历自己卡住、自己挣扎的过程——所以工具越顺手,这项能力反而越难长出来。
  • 复结构(Complex Structure):粗略地说,就是给一个几何空间装上「可以做复数运算」的坐标系统,让复分析那套工具能在上面用起来。二维球面早就装上了,而六维球面能不能装,悬了 78 年——今天的答案是能,而且是硬造出来一个。
  • MoE / 激活参数(Mixture of Experts):今天 Marin 是「5350 亿总参数、230 亿激活参数」。意思是模型里养了一大群"专家",但每处理一个 token 只叫醒其中一小撮——所以它的知识容量按 535B 算,而每次推理的计算成本只按 23B 算。这就是为什么现在的大模型参数越报越大,推理却没同比变慢。
  • 持久化提示注入(Persistent Prompt Injection):普通的提示注入是在一次对话里骗模型;持久化版本是把恶意内容写进文件名、文件内容或 URL 里躺着等,Agent 哪天顺手执行一次「列一下这个目录」就中招了。防御的难点在于:触发它的是一个完全正常的日常动作。
  • 开源权重(Open-weight):注意它和「开源」不是一回事。开源权重 = 模型参数文件公开下载,你能本地跑、能微调;但训练数据、训练代码、训练过程通常并不公开。今天英伟达要做的 Nemotron 4 走的是这条路,而 Marin 535B 罕见地把数据配比和训练过程也一并开了。
  • 完全磁盘访问(Full Disk Access):macOS 上权限最大的一档授权,批了之后应用能读取磁盘上所有受保护区域——邮件、浏览记录、Time Machine 备份都在里面,远远超出「读一下我的短信」。它一旦给出去,苹果的沙盒机制就不再是你的防线了。
  • Scaling Ladder(规模阶梯):训练超大模型之前,先按几个数量级依次训一串小模型(今天 Marin 是从 1.6B 到 27.7B 共四级)。作用有两个:把工程坑提前踩出来,以及用小模型的表现曲线去外推大模型该长什么样——如果实际曲线偏离了预测,说明出问题了,不用烧完三个月才发现。
