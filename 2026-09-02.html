HN:LLM 推理的「效率前沿」——哪些手段是在权衡,哪些是白赚 — Baseten 把推理优化手段干净地劈成两类:沿着前沿移动(纯粹的取舍)和把前沿推出去(普涨)。前者包括 batch size、并行策略(TP 适合低延迟、宽 EP 适合吞吐、ADP 拿单请求速度换吞吐);后者包括 kernel 优化、投机解码、P/D 分离。关键判断:量化同时改善延迟和吞吐,属于推前沿,而且 MXFP4/NVFP4 下「质量损失极小、收益极大」;投机解码在代码生成场景收益最大(输出可预测性高);P/D 分离主要是吞吐手段,不是延迟手段。作者反复强调这条前沿「非常锯齿状」,拐点反直觉,只能靠配置扫描实测出来。
    为什么值得关注:这是难得一篇不推销产品、只给决策框架的推理优化文章。「先分清你这一刀是在权衡还是在普涨」——有了这个分类,面对一堆优化选项时不会再乱试。

HN:48GB 的 Mac 跑 104GB 的模型,~12 tok/s——靠把专家流式读进来 — slotstream 是个纯 Swift 单二进制(不要 Python),跑 4-bit 量化后 104GB 的 Qwen3.8-Flash-Next(125B MoE)。思路:3.8GB 的稠密主干常驻内存,~68GB 的路由专家(每层 512 个、每 token 只激活 10 个)用 pread 从 SSD 按需读进一个 48 层共享的固定 slot 池——冷层的额度可以被热层借走。为什么不用 mmap?因为 MLX 无法物化部分张量,原生 loader 会「把 48GB 的机器推进 48GB 的 swap,一个 token 都没吐出来」。实测 M5 Pro 48GB:引擎 2 秒启动(只加载主干)、峰值内存 32GB、热解码 ~12 tok/s。有意思的实测结论:34GB 到 84GB 之间的缓存大小,解码和预填充速度毫无差别,所以默认就卡在 33GB。
    为什么值得关注:「slot 池 + 跨层借额度」是个可以迁移的资源调度模式。另外那句「34~84GB 之间没有任何差别」提醒我们:内存不是越多越好,拐点得测出来。

开发者实战

  1. Lobste.rs:Wasmi 2.0 深度复盘——最快的可移植 Wasm 解释器是怎么调出来的 — 八个月的引擎大改,M2 Pro 上几何平均比 1.0 快 2.2 倍。四个主要手段:①四种指令分派模式可配置(直接线程码最快但费内存、间接线程码慢 10~15% 但省内存、switch-loop 最可移植),有 auto-dispatch 自动挑;②引入累加器寄存器(ireg/freg32/freg64)常驻硬件寄存器,i64.add 从「解码结果槽、解码 LHS、解码 RHS、从栈加载、计算、写回栈、前进」七步压到三步;③把 instance 对象改成单块连续分配,字段按访问频率排序,global.get 从三次依赖加载变成一次指针偏移;④CodeMap 去掉互斥锁,改成永不重分配的追加式桶,函数体指针可直接烘进字节码。但全文最大的一个提速来自别处:发现 Rust 1.92 的 DestinationPropagation MIR pass 把条件分支的两条分派路径合并成了单个 csel、只剩一个分支点,导致 CPU 分支预测器拿到混合历史;拆开成两个独立分支点后,CoreMark 从 ~2800 涨到 4200+,单这一改就 ~50%。
    为什么值得关注:年度最佳性能工程长文之一。尤其是最后那个「编译器好心办坏事」的案例——分支预测器需要的是分离的历史,这个坑在任何解释器/状态机热循环里都可能踩到。
    实战Wasmi Labs2026-09-01
  2. Lobste.rs:ARC-AGI-1 拿到 44%,总成本 67 美分 — 做法是测试时从零训一个小 transformer(8 层,SwiGLU + RMSNorm),在租来的 RTX 5090 上从初始化到跑完全部推理,总共 67 美分。几条硬结论很有价值:①表征比什么都重要——去掉 3D RoPE 或 per-task 嵌入,任何一个,分数都会掉到 ~25% 封顶;②改成只在输出 token 上算 loss(不算输入 token),分数从 40% 提到 44%,尽管 test loss 变差了——作者直言「我不理解为什么」,并把它当成「只盯 validation loss 的一种失效模式」;③换 NorMuon 优化器解决了原版 Muon 训练后期的 loss 平台期,还省掉了手动调 LR/momentum 调度;④跨任务联合训练远胜逐任务训练(后者掉到 ~18%);⑤递归不是必需的——不用 TRM/HRM 那套递归循环和深监督也能打平。代码已开源。
    为什么值得关注:「表征 > 架构技巧」这个结论在 67 美分的成本下被做了完整消融,可信度很高。第 ② 条尤其扎心:test loss 变差但任务分数变好,提醒你评估指标选错会把优化方向整个带偏。

  3. GitHub:Copilot 代码审查现在可以「批准」PR 了——但默认全关 — 分两层:审查意见里默认带一个「批准评估」(Copilot 认为这个 PR 是否可以合并),这只是信号、不计入合并要求;管理员另外可以开启让 Copilot 提交真正的 approval 并计入 required-approvals。护栏做得比较克制:所有层级默认关闭;企业管理员可以全局锁死或下放;仓库管理员可以按文件路径限定 Copilot 能批准哪些范围;批准后如有新 commit,和人类审查者一样会被 dismiss。目前 public preview。

Hugging Face:BenchMIRT——你的 benchmark 到底在测什么能力? — AI2 把心理测量学的多维项目反应理论(MIRT) 搬来做 benchmark 审计,粒度细到单道题。用 100 个模型 × 16 个 benchmark × 3.4 万+ 道题训练,不告诉它哪个 benchmark 测什么,它自己收敛出两个主导维度:安全性和通用推理。几个尴尬发现:BBQ(社会偏见)更贴近推理维度而非安全维度,说明低分可能只是题难;WMDP(危险知识)也更贴推理——因为拒答算答对,推理越强的模型 WMDP 分越低;HarmBench 内部就是混的,标准题和情境题贴安全,版权题贴推理。另外:只保留 10% 的题目,得到的模型能力图景基本不变,保留 50% 几乎完全一致;预测留出题目的对错准确率 79%(基线 70%)。

  • 前沿安全等级 / Critical(Preparedness Framework):OpenAI 给模型危险能力划的档位,Critical 是最高档。今天 Astra 达到这一级的含义很具体——它不需要人一步步教,自己就能找到软件里没人发现过的漏洞并写出攻击程序。所以模型能力再强,也只能限量、限人、限场景地放出来。
  • 0day(零日漏洞):软件里存在但厂商还不知道、因此还没有补丁的漏洞。「零日」指的是留给厂商修复的天数是零。今天的新闻里,Astra 在测试中自己挖出了两个,这是 AI 第一次在官方公告里被承认具备这种能力。
  • MoE / 激活参数(Mixture of Experts):模型里养了一大群「专家」子网络,但每处理一个 token 只叫醒其中几个。所以会看到「35B 总参数、3B 激活参数」这种写法——占硬盘按总参数算,跑起来的速度和内存压力按激活参数算。今天两条本地推理的新闻(48GB Mac 跑 104GB 模型、Mac mini 跑 35B)能成立,全靠这个特性。
  • 投机解码(Speculative Decoding):让一个小而快的模型先「抢答」出一串 token,再让大模型一次性批量验证——猜对就白赚,猜错就丢掉重来。因为代码的下一个字符往往很好猜,所以它在代码生成场景收益最大,这也是今天 Baseten 那篇文章的重点结论之一。
  • Prompt 缓存 TTL(Time To Live):把你反复发送的那段长提示词在服务端缓存起来,再次命中就只收 1/10 甚至更低的价钱,TTL 就是这份缓存的保质期。Uber 那条新闻里最朴素也最有效的一招,就是发现工程师经常发完消息去干别的、一走神就超过 5 分钟导致缓存过期,于是把 TTL 直接改成 1 小时。
