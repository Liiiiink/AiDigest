    分工很清楚：AI 赢在需要多步推理和「魔法值」的洞（比如 bytecode handler 表在 >256MB 时的整数截断）、以及 fuzzer 语法还不支持的新特性（await using、带标签的 break）；fuzzer 赢在跨优化 pass 交互产生的非局部 bug、以及 C++ 编译器优化导致的问题——这类「看源码推不出来」的洞 AI 也看不出来。

    回溯实验更有参考价值：让 BigSleep 从单个起始 commit 去重找 2023–2026 年 112 个历史 Fuzzilli bug，复现率约 62%；换提示词和起点后升到约 70%，至少找到点什么的起点占 84%。且没检测到对训练截止前 bug 的记忆效应。

    一条反直觉结论：fuzzer 难找的 bug，AI agent 大概率也难找——难度是 bug 本身的属性，不是方法的属性。JIT 编译器这块重叠度最低，fuzzer 优势最大。

今日术语

  • 模糊测试（Fuzzing）：自动往程序里灌海量畸形输入看它崩不崩，崩了就是一个潜在漏洞；Fuzzilli 是专门针对 JS 引擎的那种，还会看代码覆盖率来指导下一步变异。
  • 提权（Privilege Escalation）：本来只有低权限的用户，利用漏洞拿到更高权限——今天 Tailscale SSH 的问题就属于这类，攻击者得先是「已授权用户」，但之后能越界。
  • 解析器差异（Parser Differential）：同一份数据被两个程序解读成不同内容。攻击者可以造一个包，让安全扫描看到的是干净文件、安装器解出来的却是恶意文件——uv 最近重写 tar 解析器就是为了堵这类口子。
  • 世界模型（World Model）：不是预测下一个词，而是预测「如果我这么做，世界会变成什么样」的模型；Genie 这类能实时生成可交互的环境画面，主要用在游戏、机器人训练和仿真。
  • JIT（即时编译）：程序跑起来之后才把热点代码编译成机器码，兼顾解释器的灵活和编译的速度——CPython 从 3.13 起试了两年多，现在要撤回去。
