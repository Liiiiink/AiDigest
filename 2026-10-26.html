PyTorch、JAX、教科书里的 softmax 全都有两个 bug，DeepMind 给了十几行的修法 — 「Softmax Collapse」是某个 logit 远大于其他时它的梯度被悄悄舍入成 0、导致梯度不再求和为零（fp32 下 Adam 默认 eps=1e-8 恰好就卡在出问题的边界上），「Softmax Cancellation」是 student 和 teacher logits 相等时仍产生非零梯度、蒸馏时学生会慢慢漂离老师；作者 Jonathan Barron 给的是代数等价的 log-softmax / softmax / cross-entropy 重写，直接替换、几乎不掉速，顺手消掉了 grokking 时的 Slingshot loss 尖刺，而且这 bug 是 Gemini Flash 3.7 先找出来并修好的。 实战
  2. 上下文工程年度盘点：六个技巧、四种失效模式，和一条「先重置上下文再说」的经验法则 — 失效模式分中毒（错误事实进来就甩不掉）、分心（上下文一长就压过模型自身知识）、混淆、冲突，对应六招是检索增强、tool loadout（有团队开场灌 600 个 skill，性能直接崩）、子 Agent 隔离、历史裁剪、落盘卸载、压缩；今年新增两种——「跟权重对着干」（模型过拟合训练时见过的工具，征兆是系统提示里全大写加重复七遍）和「上下文惯性」（长任务里死咬一个假设，改动越做越小），作者给的阈值是约 20 万 token 就该重开，用 DSPy 实现这四个修复一共只加了 16 行。 实战
  3. wordexp(3) 就是个藏在 libc 里的 shell 注入，加了 WRDE_NOCMD 也救不了 — 这个 POSIX 函数做 shell 式展开（~/foo → /home/user/foo），但默认 flags 为 0 时命令替换是开着的，传进去一个 $(whoami) 就是任意命令执行；想靠 WRDE_NOCMD 兜底也不行——musl 的实现是直接甩给系统 shell、只做表面模式扫描，漏掉 Bash 认的那些命令替换写法，macOS libc 走 helper 程序、2023 年还有同款绕过；真需要 ~ 展开就自己判断首字符再读 $HOME，别为了一个波浪号引一整套 shell 展开引擎。 实战
  4. frontdoor：扫的不是云账号里有什么，而是谁能从外面走进来 — Go 写的单二进制、只读、不要数据库不要配置文件，直接用你现成的 ~/.aws / gcloud / az 凭证，把 OIDC、SAML、跨账号信任这些「门」全列出来——一个信任 GitHub 的 role，在普通资产清单里看不出它是钉死到某个仓库某个分支还是对全 GitHub 敞开；杀手锏是跨云链路（FD031），能顺着 AWS assumed-role ARN 嵌在 GCP workload identity provider 里的痕迹拼出 GitHub → AWS → GCP → BigQuery 的完整路径，输出支持终端报告 / JSON / SARIF（传 GitHub Security 标签页）/ Mermaid 图，--fail-on 接 CI，Apache-2.0。 工具
  5. 今日术语

  • 交叉熵（Cross-Entropy）：分类和语言模型训练里最常用的损失函数，衡量模型给出的概率分布和正确答案差多远——今天 DeepMind 修的两个 bug 就藏在它和 softmax 的数值实现里。
  • 命令替换（Command Substitution）：shell 里 $(...) 这种写法，会先执行里面的命令再把输出塞回原处；任何「帮你展开字符串」的库只要没关掉它，等于给不可信输入开了执行任意命令的口子。
  • 缓存读取（Cache Read）：把重复的提示词前缀缓存在服务端，后续请求按远低于普通输入的价格复用——agent 类应用每轮都重发几万 token 上下文，所以这一项常常占到总花费的 96% 以上。
  • OIDC 联合身份（Federated Identity）：外部系统（比如 GitHub Actions）不存长期密钥，而是拿一个短期令牌去云上换临时凭证；方便，但信任条件写松一点就等于把门对全世界敞开。
