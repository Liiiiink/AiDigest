开发者实战

  1. NVIDIA 开源 SoL-Pi Harness:Token 降 64%、成本降 50%，让 AI 自己优化自己 — 韩松(Efficient AI 团队)掌舵，以 Pi 为底盘。四大机制:①动作融合——编辑+测试打包成一个本地执行序列，省掉中间决策轮次；②在线上下文压缩——只在「未来省的 > 本次重写开销」时才压缩，不乱压；③输出归档与索引——大文件输出存本地磁盘，上下文只留句柄+摘要；④证据保留归约器——小模型初筛长日志，但必须给诊断回执，系统逐条比对原始日志后才交给大模型。背后是递归自我改进(RSI)飞轮:AI 从 152 个优化方向中自动实验筛出 4 个有效机制。
    为什么值得关注:这套 Harness 的设计哲学值得每条都读——「压缩要算经济账」「摘要必须带证据回执」「编辑和测试不要分两次调模型」。它不是在模型层优化，而是在 Harness 层把浪费找出来并消除。而且它自己就是 AI 优化出来的——用 AI 降 AI 的成本，这是 Harness 效率的复利。

  2. Anthropic 工程博客:如何「contain」Claude——三层隔离的实战教训 — 三种隔离模式:①临时容器(claude.ai，gVisor，会话结束即销毁，爆炸半径最小)；②人工审核沙箱(Claude Code，macOS Seatbelt / Linux bubblewrap，写入限工作区、网络默认拒绝，减少 84% 权限提示)；③本地虚拟机(Claude Cowork，完整 Linux 内核，凭据永不进入客户机)。五个血的教训:①自定义组件最脆弱——标准化的 hypervisor/seccomp/gVisor 稳定，自定义组件出事；②信任边界前的漏洞——Claude Code 在用户同意前就解析 .claude/settings.json，攻击者可借此执行代码；③用户是注入向量——钓鱼让员工执行恶意 prompt，25 次中 24 次成功外泄 AWS 凭据；④允许域照样泄密——沙箱正常工作，但攻击者通过 api.anthropic.com 的 Files API 把数据上传到自己账户；⑤VM 隔离阻挡了 EDR——安全团队看不到虚拟机内部。
    为什么值得关注:这是目前公开可见的最诚实的 AI 安全工程文章之一——没有「我们的安全很棒」，而是逐条承认「这里出了问题」。第 ① 条(自定义组件最脆弱)和第 ④ 条(允许域照样泄密)对任何做 Agent 平台的团队都是直接警告:你的安全短板大概率在自己写的代码里，不在操作系统那层。

  3. Mistral:用 AI Agent 把 4 万行 Fortran 77 迁移到 C++——三条原则和三次翻车 — 帮一家欧洲能源运营商迁移油藏模拟器。三条原则:①先建校验框架(数值一致性是唯一的可信证明)；②先整理文档(AI 解析 Fortran 调用树，从叶到根逐节点自动生成文档)；③结构化工作流优于全自主或纯手动(人操作 coder/tester/reviewer Agent 工作流)。三次翻车:①全自主——Agent 把 Fortran 逐行翻译成 C++ 语法，GOTO 全保留；②多角色协作——质量提升但 Agent 遇 bug 后卡住无人介入；③最终方案——结构化工作流 + 人工检查点。首次冲刺覆盖 30 万行中的 4 万行核心功能。
    为什么值得关注:这篇文章的价值不在「AI 成功迁移了 Fortran」，而在它诚实地记录了前两次翻车——全自主 Agent 只会做语法翻译而非架构重构，多 Agent 协作会卡在 bug 上等死。最终收敛到的「结构化工作流 + 人工检查点」是务实的中间路线。第 ① 条原则也通用:做任何代码迁移，先建数值校验框架，这是唯一不会骗你的东西。

  4. LangChain:多 Agent 上下文的 Fork 模式——让子 Agent 继承主 Agent 的对话历史 — 传统多 Agent 架构中，子 Agent 从空白上下文启动，重复收集主 Agent 已经做过的工作。Fork 模式让子 Agent 继承主 Agent 的完整对话历史，利用 prompt caching 反而更快更便宜。四种 Agent 类型的推荐模式:Worker(实现修复)→ Fork；Verifier(独立评估)→ Isolated(避免被主 Agent 的诊断锚定)；Researcher(自包含问题)→ Isolated(可并行)；Memory(提取记忆)→ Fork(需要全局视角)。已在 deepagents 框架实现，支持 Python/TypeScript。
    为什么值得关注:多 Agent 上下文管理是当下 Agent 平台最脏的工程问题。Fork vs Isolated 这个二分法简洁且正确——需要独立的给空白、需要继承的给 Fork。那条「Verifier 必须隔离，避免被主 Agent 的诊断锚定」尤其重要:如果你让 Reviewer 看到你自认为「可能出问题的地方」，它就不会自己找了。
    实战LangChain2026-09-08
  5. Shopify Gisting:把 6000 token 系统提示词压缩到 1500，4:1 压缩比且不损质量 — 通过「教师-学生」训练:教师侧用原始提示词、学生侧用 Gist token，最小化两者 KL 散度。训练完成后 Gist 嵌入写入模型嵌入矩阵，推理时无需额外编码器或特殊路径。实测:TTFT 从 438ms→354ms、端到端延迟 6.8s→4.2s、吞吐量 20.2→23.4 QPS。可与前缀缓存叠加使用——前缀缓存省 KV 重复计算，Gisting 缩短序列省解码开销。
    为什么值得关注:系统提示词越长越贵是普遍痛点(GitHub Copilot 的系统提示词据说有几千字)。Gisting 的精妙之处在于它不是简单的文本摘要，而是学出来的压缩表征——模型「理解」的是压缩版而非原文摘要。而且跟前缀缓存可叠加，效果乘数级。
    实战Shopify / InfoQ2026-09-09
