一、Agent 基础概念

Q1:什么是 AI Agent?和普通聊天机器人(Chatbot)有什么区别?

Agent = 能「自主规划 + 调用工具 + 多步行动」的 LLM 系统;Chatbot 只是"你问我答"的对话。

  • 核心区别在目标驱动:你给 Chatbot 一个问题,给 Agent 一个目标——它自己拆解任务、规划步骤、调用工具、执行并纠错,直到完成。
  • 举例:让 Chatbot"查天气",它只能"说";让 Agent"订明早去上海最便宜的机票",它会自己搜、比价、下单。
  • 面试一句话:Chatbot 是对话,Agent 是代办。

Q2:Agent 的四大核心组件是什么(必背)?

规划(Planning)、记忆(Memory)、工具使用(Tools)、行动(Action)。

  • 规划 Planning:把大目标拆成小步骤(任务分解、反思、自我批评)。
  • 记忆 Memory:短期(当前对话上下文)+ 长期(向量库等外部存储)。
  • 工具 Tools:调外部能力——搜索、计算器、API、代码执行、数据库。
  • 行动 Action:按规划执行每一步,并根据结果动态调整。

Q3:Agent 和「工作流 Workflow」是一回事吗?

不是。区别在于谁在决定流程走向。

  • Workflow:路径由人预先写死(A→B→C 固定),LLM 只在某些节点干活。
  • Agent:路径由模型动态决定(它自己决定下一步做什么、调哪个工具),人是放权的。
  • Anthropic 的经典区分:workflow 是"编排好的流水线",agent 是"模型自主驾驶的循环"。面试常考这个边界。

二、核心架构与范式

Q4:什么是 ReAct?为什么说它是 Agent 的基石范式?

ReAct = 推理(Reasoning)+ 行动(Acting)交替进行的范式:模型先"想"(Thought),再"做"(Action,调工具),拿到结果(Observation),再想下一步,循环直到完成。

  • 价值:把"内心推理"显式写出来,让模型边想边做、边做边修正,而不是一口气瞎猜。
  • 记忆口诀:想→做→看→再想,直到有答案。
  • 面试追问:ReAct 怎么减少幻觉?——把结论锚定到工具返回的真实结果上,而不是全凭模型记忆。

Q5:ReAct 和 Plan-and-Execute 有什么区别?

ReAct 是"边想边做"(边规划边执行),Plan-and-Execute 是"先规划后执行"。

  • ReAct:走一步看一步,灵活、能及时纠错;但容易短视、绕远路。
  • Plan-and-Execute:先一次性列出完整计划,再逐步执行;更全局、更少跑偏,但计划错了要重来、不够灵活。
  • 面试点:能说清"一个全局但僵硬,一个灵活但短视",并能各举一个适用场景。

Q6:什么是 Reflexion(反思)?它怎么提升 Agent 可靠性?

Reflexion = 让 Agent 在失败后自我复盘,把"哪错了、下次怎么改"写进记忆,下轮做得更好。

  • 本质:把"错误经验"从上下文里提炼成文字教训存起来,跨轮复用。
  • 和 ReAct 的关系:ReAct 是单次"想-做"循环,Reflexion 是在此之上加了跨次的自我改进。
  • 一句话:让 Agent 长记性。

三、工具调用与 MCP(高频)

Q7:什么是 Function Calling(函数调用)?它解决了什么痛点?

Function Calling = 让模型按约定格式输出"要调哪个函数、带什么参数",由程序去真正执行,再把结果喂回模型。

  • 解决的痛点:让只会输出文字的模型,能可靠地触发外部动作(查库、发请求、控设备)。
  • 关键:模型不直接执行,它只是"决定要调什么、参数是什么",真正执行的是你的代码。
  • 面试点:模型输出的是结构化参数(JSON),程序负责执行和兜底(校验、权限、重试)。

Q8:MCP 是什么?为什么 2024 底突然火了?

MCP(Model Context Protocol,模型上下文协议)= 一个开放标准,统一规范"AI 应用怎么连外部的数据源和工具"。

  • 类比:像 AI 界的 USB-C 接口——工具/数据源只要按 MCP 标准做一个"Server",任何支持 MCP 的 AI 客户端都能即插即用,不用一家家定制对接。
  • 解决的痛点:之前每个工具都要为每个模型/应用单独写适配(N×M 问题);MCP 把它变成"一次实现,处处可用"。
  • 组成:MCP Server(提供工具/数据的一方)+ MCP Client(调用的一方,如 Claude、IDE)。
  • 面试一句话:MCP 是工具接入的统一标准协议,让"接工具"从定制开发变成标准插拔。

Q9:MCP 和 Function Calling 是一回事吗?

不是,是互补的两层。

  • Function Calling:模型怎么表达"我要调这个函数"(一种输出格式/能力),是模型侧的"说话方式"。
  • MCP:工具怎么被发现、被连接(一套通信协议/标准),是系统侧的"插座标准"。
  • 关系:模型用 Function Calling 发起调用,调用可以经由 MCP 这样的协议路由到具体工具。可以类比:FC 是"普通话",MCP 是"电网接口"。

四、记忆机制

Q10:Agent 的「短期记忆」和「长期记忆」分别靠什么实现?

  • 短期记忆:靠上下文窗口(把最近的对话/步骤直接放进 prompt)。特点:快、但受窗口长度限制,会"忘"。
  • 长期记忆:靠外部存储 + 检索(典型是向量数据库),需要时把相关记忆检索回来塞进上下文。特点:容量大、可持久。
  • 面试点:短期=窗口内,长期=检索增强。两者常配合用。

Q11:RAG(检索增强生成)是什么?和微调有什么区别?

RAG = 先从知识库检索相关内容,再把检索结果拼进 prompt 让模型基于它作答。

  • RAG:不改模型,外接知识。优点:知识可更新、可追溯(有出处)、成本低;缺点:依赖检索质量。
  • 微调 Fine-tuning:用数据训练/改模型权重,把知识"烙进"模型。优点:风格/行为更稳;缺点:贵、知识固化、难更新、可能遗忘。
  • 面试一句话:RAG 给模型"查资料",微调给模型"做训练"——要新鲜/可溯源的知识选 RAG,要固化行为/风格选微调。

五、主流框架

Q12:LangChain 和 LangGraph 有什么区别?什么时候用哪个?

  • LangChain:一套组件库/抽象(模型、prompt、工具、链),帮你快速搭 LLM 应用,适合线性/简单流程。
  • LangGraph:在 LangChain 之上,把 Agent 流程建成有状态的图(Graph),支持循环、分支、持久化状态、多智能体,适合复杂、需要循环/状态的 Agent。
  • 一句话:简单链式用 LangChain,复杂带状态/循环的 Agent 用 LangGraph。

Q13:AutoGPT、CrewAI、Dify、Coze 各是什么定位?

  • AutoGPT:早期"自主 Agent"代表,给一个目标自己拆解执行(演示意义大,生产需打磨)。
  • CrewAI:多智能体协作框架,给不同 Agent 分配角色(研究员、写手、审稿人…)协同完成任务。
  • Dify / Coze(扣子):低代码/可视化的 Agent 与应用搭建平台,拖拖拽拽就能做出带工具、知识库的 AI 应用,适合快速落地和非纯研发团队。

六、多智能体(Multi-Agent)

Q14:什么时候该用「多智能体」而不是一个更强的单 Agent?

当任务能自然拆成不同角色/专长,或需要并行与互相校验时。

  • 适合:职责清晰可分工(研究+写作+审稿)、需要多视角互查、子任务可并行。
  • 代价:更复杂、更贵、更难调试(错误会沿链路放大)。能用单 Agent 解决的,别硬上多智能体。
  • 面试点:多智能体不是越多越好,编排(orchestration)和明确分工才是关键。

七、评估与安全

Q15:怎么评估一个 Agent 好不好用?为什么比评模型难?

  • 常用维度:任务完成率(到底做成没有)、步骤效率(绕不绕路)、工具调用正确率、成本/时延、轨迹可观察性(能不能回看它每步怎么想的)。
  • 难点:Agent 是多步、带外部交互的系统,错可能出在任一步(规划错/工具错/记忆错),不能只看最终输出,要看完整轨迹(trajectory)逐步归因。

Q16:Agent 有哪些典型安全风险?怎么缓解?

  • 风险:提示注入(恶意网页/邮件诱导它干坏事)、越权操作(删库/乱发消息/乱付款)、幻觉驱动的错误动作、数据泄露。
  • 缓解:最小权限(只给必需的工具和权限)、关键操作人工确认(human-in-the-loop)、输入消毒 + 工具白名单、操作审计日志、沙箱执行。
  • 一句话:能力越大,越要把权限和风险关进笼子。

八、高频面试速答(易混辨析)

  • Agent vs Chatbot:Agent 自主规划+调工具+多步行动;Chatbot 以对话问答为主。
  • ReAct vs Plan-and-Execute:边想边做(灵活)vs 先规划后执行(全局)。
  • RAG vs 微调:外接知识库(可更新、可溯源)vs 改模型权重(固化行为)。
  • MCP vs Function Calling:工具接入的统一协议(插座)vs 模型表达调用的格式(说话方式)。
  • 短期 vs 长期记忆:上下文窗口 vs 外部检索(向量库)。
  • LangChain vs LangGraph:组件库(线性)vs 状态图(循环/多智能体)。
