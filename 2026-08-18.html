GitHub 官方博客:Canvas 让 agentic workflow 可视、可控、省钱 — GitHub Copilot 团队 8 月 17 日发布的工程博客，指出了一个被普遍忽视的痛点：纯聊天界面里，Agent 的工作产出会在滚动中丢失——上下文越长越难追溯、难干预、难审计。GitHub 的解法是 Canvas（画布）界面：把 Agent 的任务分解、中间产物、决策点、人工干预入口全部平铺在一个可视化画布上，开发者可以定点编辑、回滚、分支、审计。文章给出实测数据：相比纯聊天，Canvas 让 agentic 任务的 token 消耗降低、人工干预次数减少、最终交付质量更稳定。

  4. Rootly 用 AI Agent 重构 code review，直接废止了「小 PR」规则 — InfoQ 报道。Rootly(Incident 管理公司）的工程团队做了一个激进决定：取消「PR 必须小于 X 行」的规定。原因是他们引入了 AI Agent 做初审——AI 能在几秒内读完几千行 diff、给出结构化审查意见、标记真正的风险点。人类 reviewer 不再需要「小 PR 才看得过来」，而是聚焦在 AI 标出的 2-3 个高风险区域。结果是:合并速度提升、大重构不再被人为拆分、review 质量反而上升——因为 AI 不会累、不会跳读、不会「看着像就过」。文章也讲了配套机制:AI 初审不通过不能直接合、人类必须确认 AI 标记的每一处、敏感模块仍强制双人审查。

  • AI;DR(AI; Didn't Read):HN 今天造出来的新词，戏仿「TL;DR(太长没读)」。意思是:当任何东西都能被 AI 一秒生成，阅读本身就成了最稀缺的资源——很多文档、PR 描述、会议纪要发出去之前，作者就知道没人会读，只是「为了触发 AI 摘要」。它指向一个真问题：当写作成本趋近于零，未被阅读的内容就都是噪音。
