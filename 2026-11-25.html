    流程是这样的:agent 扫开源代码或读厂商披露 → 在运维自己的机器上复现并验证这个 exploit → 据此生成一段 eBPF(或应用字节码)屏障 → 人看过证据、批准之后,屏障热加载进正在跑的服务,不用重启。要点是「人批准」这一步没被省掉,证据链是产出物的一部分。

今日术语

  • eBPF:一种让你把小程序挂到正在运行的 Linux 内核里特定位置执行的机制,不用改内核源码也不用重启。Shirudo 用它在不停服的前提下把「拦截动作」插进去。
  • 签名屏障(Signed Shield):Shirudo 生成的那段防御代码带加密签名,内核加载前先验签,防止别人塞一段伪造的「防御」进来。配 TPM 还能留一份谁在什么时候装过/摘过的可验证记录。
  • MCP(Model Context Protocol):一套让 AI agent 跟外部工具/数据源对话的开放协议。今天 Google 把它从「一种可选接法」升级成了 Workspace agent 的唯一合规通道。
  • Code Mode:让模型写一段代码来批量调用工具,而不是一次发一个工具调用请求。好处是多步操作能在一段脚本里跑完,省往返、省上下文。
  • CWE-306(关键功能缺失认证):某个本该要求登录/鉴权的接口压根没做校验,谁能访问到就能用——今天 cnpmcore 这个 CVE 就属于这类。
