全景图:全家桶各件是干什么的

┌───────────────────────────────────────────────────┐
│ Deep Agents    开箱即用的完整 Agent(含 CLI dcode)  │
│                规划 / 子 Agent / 上下文压缩 / 虚拟FS │
├───────────────────────────────────────────────────┤
│ LangChain v1   create_agent + middleware          │
│                模型 / 工具 / 记忆 / 结构化输出        │
├───────────────────────────────────────────────────┤
│ LangGraph      底层编排运行时(可脱离 LangChain 单用) │
│                状态图 / 断点恢复 / 人工介入           │
├───────────────────────────────────────────────────┤
│ LangSmith      平台:Trace 观测 / 评测 / 部署 / 网关  │
└───────────────────────────────────────────────────┘
  • LangChain(v1):写 Agent 的主框架。核心 API 是 create_agent——一个「最小但高度可配」的 harness;模型用字符串指定(如 "claude-sonnet-4-6"、"openai:gpt-5.5"),换模型只改一个字符串;能力靠 middleware 按需叠加。
  • LangGraph:低层编排框架,把「确定性代码步骤」和「LLM 步骤」编进同一张状态图。提供持久化执行(崩了从断点续跑)、interrupt(任意节点暂停等人审)、短期/长期记忆。LangChain 的 Agent 底层就跑在它上面,但 LangGraph 可以独立使用。
  • LangSmith:商业化平台,覆盖 Agent 全生命周期——Observability(trace/调试/线上观测)、Evaluation(数据集+评测器+prompt 管理)、Deployment(部署扩容,Cloud/BYOC/自托管)、LLM Gateway(跨厂商流量路由/管控)、Fleet(无代码搭 Agent)、Engine(自动发现 recurring 问题并建议修复)。
  • Deep Agents:「batteries-included」的完整 Agent——自动上下文压缩、虚拟文件系统、能派生子 Agent,构建在 LangChain agents 之上;附开源 CLI dcode,终端里直接体验。
  • 已淡出的旧成员:LangServe 不再单独推荐(能力并入 LangSmith Deployment);LCEL/Chain(| 管道、LLMChain、create_react_agent)是 2024~2025 中教程的主角,底层还在,但已不是官方叙事中心——抄教程前先认年代。

核心概念速通(后端视角对照)

  • Agent = Model + Harness:模型是可替换的引擎,harness 是围着它的循环(提示词、工具、中间件)。类比:模型 ≈ 数据库,harness ≈ Web 框架。
  • tools = 普通函数:带类型注解 + docstring 即可注册,docstring 就是给模型看的工具说明——相当于「写 Javadoc 顺便发布了接口」。
  • middleware ≈ Spring Interceptor / AOP:guardrails、重试、路由等横切能力,以列表形式挂进 create_agent,官方有预构建件也可自定义。
  • messages / content_blocks:对话状态的标准结构;invoke 返回里取 result["messages"][-1].content_blocks 拿到结构化输出。
  • memory 两层:短期(thread 内对话状态,靠 checkpointer 持久化)与长期(跨会话记忆)。
  • structured output / streaming / event streaming:结构化输出直接绑定 Pydantic 模型;流式分 token 流与事件流,前者给用户看,后者给程序消费。
  • LangGraph ≈ 工作流引擎 + 状态机:StateGraph 定义状态,节点是确定性代码或 LLM 调用,边支持条件分支;checkpointer ≈ 流程实例表(断点恢复),interrupt ≈ 人工审批节点。
  • LangSmith trace ≈ LLM 版 OpenTelemetry:每一次模型调用、工具调用、耗时、token、成本全留痕;dataset + evaluator ≈ 单测 + 回归测试。

30 分钟跑通(最小上手)

1) 安装与开关(顺手把追踪开了,后面调试全靠它):

pip install -U langchain "langchain[anthropic]"   # 或 "langchain[openai]"
export ANTHROPIC_API_KEY=sk-...
export LANGSMITH_TRACING=true

2) 最小 Agent(带一个工具):

from langchain.agents import create_agent

def get_weather(city: str) -> str:
    """查询指定城市的天气。"""
    return f"{city} 晴,26°C"

agent = create_agent(
    model="claude-sonnet-4-6",      # 换模型只改这一个字符串
    tools=[get_weather],
    system_prompt="你是一个靠谱的助手",
)
result = agent.invoke({"messages": [{"role": "user", "content": "新加坡今天天气?"}]})
print(result["messages"][-1].content_blocks)

3) 按需加 middleware:guardrails / 重试 / 模型路由等都是 middleware,以列表传入 create_agent(middleware=[...]) 即可;先用预构建件,不够再自定义。

4) LangGraph hello world(需要显式编排时):

from typing import TypedDict
from langgraph.graph import StateGraph, START, END

class State(TypedDict):
    text: str

def shout(state: State):
    return {"text": state["text"].upper() + "!"}

g = StateGraph(State)
g.add_node("shout", shout)
g.add_edge(START, "shout")
g.add_edge("shout", END)
app = g.compile()
print(app.invoke({"text": "hello langgraph"}))

5) 打开 smith.langchain.com 看刚才每一次调用的完整 trace——输入输出、耗时、token、成本都在里面。

四周学习路径

  • W1 · 跑通:官方 quickstart 跑一遍 → 同一 Agent 换 3 家模型(改字符串)→ 写 3 个真实 tool(读数据库 / 调内部接口 / 查日志)。产出:一个能在公司内网干活的玩具 Agent。
  • W2 · 工程化:structured output(绑 Pydantic)、streaming 两种流、thread 级短期记忆、给 Agent 组合 2~3 个 middleware。产出:一个带结构化返回和护栏的接口。
  • W3 · 编排:LangGraph 状态图 + 条件分支 → 加 checkpointer 演示「杀掉进程再续跑」→ 加 interrupt 做人工审批节点。重点想清:什么时候才该从 create_agent 下到 LangGraph(需要确定性流程 / 持久化 / 人工介入时)。
  • W4 · 上线:LangSmith 建评测数据集 + 写 evaluator → 跑回归 → 线上 trace 看板 + 成本/延迟监控 → 选部署方式(LangSmith Deployment / 自托管)。产出:一条「能持续交付」的 Agent 流水线。

常见坑

  • 版本割裂是第一坑:网上 2024~2025 年中的教程大多是 LCEL 时代写法(| 管道、LLMChain、create_react_agent),与 v1 的 create_agent 世界画风完全不同。看任何教程先确认写作年代。
  • 别上来就 LangGraph:create_agent 能搞定的不要画图;图是「需要精确控制时的逃生舱」,不是起点。
  • 先开 tracing 再调试:盲改 prompt 是最慢的调试方式;trace 里能直接看到模型每步「为什么这么决定」。
  • LangSmith 免费档够个人学,团队再考虑 Cloud / BYOC / 自托管;trace 会带数据,涉敏感业务先评估数据边界。
  • 工具函数就是执行体:别把未校验的用户输入直接拼进 SQL / shell——和写后端同一个道理,只是调用方从人变成了模型。
  • Deep Agents 适合「想要完整 Agent 但不想自己拼」;装个 CLI dcode 在终端里体验一圈,能直观理解上下文压缩和子 Agent 是怎么回事。
