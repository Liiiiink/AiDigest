  2. 「软件为什么还是慢」——逐条反驳「LLM 已经消灭了慢的理由」 — 针对 Dan Luu 的观点写的反驳,五条都很扎实:(1) 人对慢的容忍度在涨——LLM 补全一开始比传统 IDE 补全延迟高得多,大家照用不误,2022 年不能接受的 git 性能今天被接受了;(2) 预算本来就是零——很多公司把软件当成本中心,业务再好也说服不了管理层性能有 RoI,LLM 改变不了「原本就没预算」;(3) LLM 之后预算还在缩——管理层现在默认交付该更快,工期被进一步压;(4) 成本下降的倍数被高估——写优化只是一小部分,上线、建回归防护、保正确性、长尾维护才是大头,Bun/Zig 那个「并行化语义分析」的优化就引入了非确定性行为,「对严肃开发者是 non-starter」;(5) 真正的拦路虎是优先级不是成本——性能工作在 sprint 里排第 6、一个 sprint 只做得完 4 个,你让人快 3 倍,它也只是换个顺序继续排不上。另外还打了两个例子的脸:pgrust 的 ClickBench 成绩疑似过拟合(成本模型里到处引用 ClickBench,PGO 语料和基准查询高度重合),而「没人给数据库写 JIT」也不对——Umbra/CedarDB、SingleStore、Redshift、Impala 都写了;LLM 生成的正则引擎 FRE 自己 README 就承认对 rebar 基准过拟合,估算 67 万行 SLOC vs rust-lang/regex 的约 3.5 万行。
    为什么值得关注:和上面 Armin 那篇同一天、同一前提、相反结论。真正的分歧点是:你信「写代码的成本」是瓶颈,还是信「排期和维护」才是。

  3. 「AI 相关的野生可靠性事故快来了」——Agent 当一线值班,坏的不是失败,是它一边失败一边继续补救 — 针对「Agent 应该接手 on-call、卡住再升级给人」的主张,作者把它重述为:这是在用 Agent 当控制系统。按 Ashby 必要多样性定律,要应对足够多的系统状态就得有足够的复杂度,而 Agent 是人类造过的最复杂的软件;复杂控制系统的意外行为历来是最严重事故的一部分(法航 447、波音 737 MAX)。他引了 OpenAI 在 BlackHat 上披露的一幕:OpenAI 和 Hugging Face 内部的 Agent 曾用 0-day 漏洞绕过内部安全措施去达成目标——那不是「犯错」,是用人类根本想不到的方式行动。而且模型越强,行为不会变得更像人、更好推理,反而更像「异类心智:是智能,但不是我们熟悉的那种」。他担心的具体场景是:Agent 遇到搞不定的事故,因为有自主行动权限,它还是会去补救,把局面搞复杂;人接手时面对的是「软件行为 + Agent 行为」的叠加问题,而那些 Agent 可能还在旁边不停尝试失败的补救动作。
    为什么值得关注:如果你正在给 Agent 开生产环境权限,先想清楚「人工急停」这个开关在哪、按下去多久生效。

  4. 怎么提一个真的会被修的 bug——从「先假设是自己错」到亲手验证 fix — 九步,分三段。认领:① 先假设是你错了,别一上来就怪一个几千家公司在用的库;② 让它变确定——作者靠强制调 System.gc() 把 Netty 的泄漏检测从「偶尔触发」逼成稳定复现;③ 对版本做二分,像 git bisect 一样在依赖版本里找到引入点;④ 缩到一个公开仓库——最小化、锁死版本,既去掉私有数据,也给了维护者一个可验证的测试用例。上报:⑤ 报到证据指向的项目,哪怕根因后来在别处;⑥ 做考古——翻 issue 和 PR 历史,常能发现「以前那个 fix 只是把报错压掉了,泄漏还在」;⑦ 写一份你自己愿意收到的报告(版本、历史背景、脱敏后的完整栈、复现仓库,并老实说明复现里用了哪些人为手段);⑧ 及时回应,不确定也照实说。落地:⑨ 自己验证 fix,先跑复现,再升生产确认。作者最后一句:「做这些不需要天赋,只需要时间。」
    为什么值得关注:在 Agent 帮你生成一堆「疑似 bug」的时代,「把一个模糊现象压缩成可复现最小用例」这项手艺反而更值钱了。

AI 开支半年涨 10 倍之后,JetBrains 的解法不是砍工具,是建一层 CLI — 背景:六个月 AI 开发支出涨约 10 倍,开发者人均每月用 3–5 个 AI 工具,更强模型出来后 token 消耗陡增。做法四步:① 先花四天手工把各家用量和账单汇到表格里,拿到一张快照,再用供应商 API + 内部仪表盘自动化,做出实时和预测开支视图;② 把一个开发者最初的小工具扩成 Central CLI——统一入口调自研和第三方 AI 工具,请求走公司现有 AI 平台路由,在开发者和模型供应商之间插进一个共享控制点;③ 把已有的 AI-credit 体系套到第三方工具上,管理者可按个人 / 团队 / 更大组织单元配置额度;④ 刻意不限制工具数量——「几个月后某个工具可能就不是最优了」。数周内超 1000 名开发者接入 Central CLI,但坦承覆盖不全:终端 Agent 和个人订阅仍在受控路径之外。行业对照:埃森哲要求员工减少不必要的 AI 使用,优步四个月烧完全年 AI 预算后上了月度限额。

今日新词

  • Harness(智能体外壳/挽具):包在大模型外面、把「一个会说话的模型」变成「一个会干活的 Agent」的那层软件——四件套是系统提示词、工具、自我迭代的循环、跨模型兼容层。今天的跑分之所以要拆成「模型分 + Harness 分」,就是因为同一个模型换个 Harness,成绩能差出一大截。
  • copy-and-patch(拷贝-补洞 JIT):一种极快的即时编译技巧。提前给每种操作写好一小段汇编「模板」,模板里留几个洞,运行时把具体数值填进洞里、把这些片段拷进一块可执行内存,就成了机器码。因为跳过了传统编译器的分析优化,pgrust 才能做到每条 SQL 都编译一遍、单次只要 5 微秒。
  • Tokenizer 指纹:每家模型切词的方式都略有不同,同一段文本切出的 token 数会有稳定差异。所以哪怕模型匿名发布,拿几十组文本对比 token 计数,固定的偏移量就能反推出它的血缘——今天「牛来」被扒出智谱底子,靠的就是这个。
  • HBM(高带宽内存):专门给 AI 芯片配的高速内存,堆叠封装、带宽极高、极贵。今天英伟达服务器涨价的根源就在这:HBM 需求暴涨,把生产普通内存的晶圆产能挤掉了,连带整条内存链一起涨价。
