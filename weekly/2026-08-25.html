模型精讲:Scaling Laws(缩放定律)——大模型为什么"越大越强",以及这句话错在哪

同样的钱,是该训一个"大块头"还是"多读书"?这条定律给出了可计算的答案

核心看点:损失(loss)会随模型大小、数据量、算力按幂律可预测地下降——这意味着大厂能用小实验外推出千亿模型的效果。而 2022 年 Chinchilla 一篇论文推翻了前人结论,证明当时几乎所有主流大模型都训练不足。

它是什么

  • Scaling Laws(缩放定律) 是一条经验规律:训练损失随着模型参数量 N、数据量 D(token 数)、算力 C 的增长而平滑下降,且下降曲线遵循幂律(power law)——在对数坐标纸上画出来是一条直线。
  • 三个关键符号要记住:N = 参数量,D = 训练 token 数,C ≈ 6ND = 训练所需算力(其中前向传播占 2ND,反向传播占 4ND)。
  • 还有一项 E(不可约损失):再怎么加钱也降不到 0,语言本身的随机性构成了地板。

为什么重要

  • 它把"炼丹"变成了"工程预算"。最实用的价值在于:可以先跑几个便宜的小实验拟合出曲线,再外推预测"我花 1 亿美金训个千亿模型,效果大概到哪"——不必真烧钱试错。
  • 它决定了钱怎么分。给定固定预算,参数和数据的配比不同,最终效果天差地别。这不是学术细节,而是每个大模型团队开工前的第一道计算题。
  • 它是"大模型军备竞赛"的理论依据:正因为效果可预测地随投入增长,资本才敢持续往里砸钱。

它是怎么工作的:一场著名的"路线之争"

第一回合 · Kaplan(2020)——"模型要大"

  • OpenAI 的 Kaplan 等人首次把缩放定律带火。核心结论有几条:大模型样本效率更高(用更少数据就能达到同样损失);架构细节远不如规模重要。
  • 最有影响、也最具争议的一条:算力固定时,应该训一个超大模型、不等收敛就停,而不是训小模型到收敛。
  • 具体建议:算力增加 10 倍,模型规模应扩大 5.5 倍,而 token 只需增加 1.8 倍——重模型、轻数据。

第二回合 · Chinchilla(2022)——"数据要跟上"

  • DeepMind 扫了超过 400 个模型(70M~16B 参数,5B~500B token)重做实验,结论直接反转:模型每翻一倍,训练数据也该翻一倍——两者应等速增长。
  • 教科书级的实锤对照:在与 Gopher(280B 参数 / 300B token)完全相同的算力预算下,他们训了 Chinchilla(70B 参数 / 1.4T token)——参数小 4 倍、数据多 4 倍——结果全面胜出。
  • 这个实验证明了一件让整个行业尴尬的事:当时的主流大模型普遍"训练不足"——不是脑子不够大,是书读得太少。

为什么两家结论会打架?

  • 实验规模不同:Kaplan 主要在小模型上做实验,而 log-log 图上拟合线斜率的一点点误差,外推到大模型就是巨大偏差。
  • 参数怎么数:Kaplan 不算 embedding 参数,Chinchilla 算。在小模型区间 embedding 占比不可忽略,两种口径下"参数量"甚至不再是一条干净的幂律。
进阶点一(为什么偏偏是幂律?):目前主要有两种解释。一是流形分割假说:语言数据其实分布在一个低维流形上,参数越多,对流形的切分越细,分辨率按 N^(-1/d) 提升。二是技能量子化假说:知识以离散"技能块"存在、其出现频率本身服从幂律,模型先学会高频技能、再学低频的,叠加起来就表现为平滑的幂律下降。
进阶点二(数据墙:书快读完了怎么办?):经典缩放定律假设数据无限且不重复,但高质量语料正在耗尽。Muennighoff 等人的研究给重复数据做"指数折价",结论是:多余参数的贬值速度快于重复数据——所以数据不够时,该多跑几轮 epoch,而不是继续堆参数。2026 年 Lovelace 等人进一步发现:模型越大,对数据重复越敏感;而加大权重衰减(weight decay)可以缓解重复训练带来的过拟合惩罚。
一个反直觉的提醒:缩放定律公式很漂亮,拟合过程却异常脆弱。有研究复查 Chinchilla 的拟合方法,发现优化器设置(Huber loss 取平均而非求和)导致过早终止优化,加上论文里系数只保留 2 位小数,让结果看起来比实际更矛盾。别把这条"定律"当物理定律用。

动手教程:写一个 MCP 服务器,给 Claude 装上你自己的"外挂"

MCP 是 AI 应用的"USB-C 接口":30 行 Python,让 Claude 用上你私有的数据和工具

你将做出:一个跑在本地的 MCP 服务器。写完之后,Claude 桌面端里会多出你亲手做的工具——你问它问题,它会自己决定调用你写的那个 Python 函数。

准备:

  • Python 3.10+,以及包管理器 uv(下面第 1 步会装)。
  • MCP Python SDK 2.0+(注意:v2 的 API 与网上大量 v1 老教程不兼容,详见下方提醒)。
  • Claude 桌面端(免费版即可),装好并更新到最新。
  • 无需 GPU、无需 API Key——服务器纯跑在你自己电脑上。

跟着做:

  1. 装 uv 并建项目(约 3 分钟):

    ```bash

    curl -LsSf https://astral.sh/uv/install.sh | sh

    # 装完重启终端,然后:

    uv init myserver && cd myserver

    uv venv && source .venv/bin/activate

    uv add "mcp[cli]"

    touch server.py

    ```

  2. 写服务器:把下面内容存进 server.py。整个服务器就这么长——注意没有一行 JSON Schema:

    ```python

    from mcp.server import MCPServer

mcp = MCPServer("Demo")

@mcp.tool() def add(a: int, b: int) -> int: """Add two numbers.""" return a + b

@mcp.resource("greeting://{name}") def greeting(name: str) -> str: """Greet someone by name.""" return f"Hello, {name}!"

if __name__ == "__main__": mcp.run(transport="stdio") `` 这里藏着 MCP 最妙的设计:**Python 的类型标注本身就是 Schema**(a: int, b: int 就够了),**docstring 就是给模型看的工具说明**。模型靠这两样"读懂"你的工具——和上上期 smolagents 的 @tool` 是同一套哲学。

  1. 先在调试器里跑通(强烈建议,别跳):

    ```bash

    uv run mcp dev server.py

    ```

    这会打开官方的 MCP Inspector,你可以在网页里手动点一下 add 工具、传参数、看返回值——先确认服务器本身没问题,再去接 Claude,能省掉一大半排错时间。

  2. 接进 Claude 桌面端:打开配置文件(macOS 路径如下,Linux 是 ~/.config/Claude/claude_desktop_config.json):

    ```bash

    code ~/Library/Application\ Support/Claude/claude_desktop_config.json

    ```

    填入(文件不存在就新建):

    ```json

    {

    "mcpServers": {

    "demo": {

    "command": "uv",

    "args": ["--directory", "/你的绝对路径/myserver", "run", "server.py"]

    }

    }

    }

    ```

    三个高频翻车点:① 路径必须是绝对路径(在项目目录跑 pwd 复制);② command 里的 uv 可能需要写全路径(用 which uv 查);③ Windows 的 JSON 路径要用 \\ 或 /。改完重启 Claude 桌面端。

  3. 验收:重启后点输入框旁的 "+",在 Connectors 里应该能看到你的 demo 服务器。然后问它一句"帮我算 3 加 5",观察它主动调用你写的 add 函数——那一刻你会真正理解 Agent 的工具调用是怎么回事。
两个必须知道的坑: - 别用 print()。stdio 模式下,任何写进 stdout 的内容都会污染 JSON-RPC 消息、直接搞崩服务器。要打日志请用标准库 logging(它写 stderr,安全)。 - 认准 v2 API。老教程里的 FastMCP 是 v1 的写法;当前 v2 SDK 用的是 from mcp.server import MCPServer。照抄老代码会直接 ImportError。
做完你会:拥有一个可以无限扩展的模板——把 add 换成"查我司数据库""读我的笔记""调我们内部 API",Claude 就接上了你的私有世界。这正是 MCP 被称为"AI 应用的 USB-C 接口"的原因:工具只写一遍,任何支持 MCP 的客户端都能用。下一步可探索:用 uv run mcp run server.py --transport streamable-http 把它跑成 HTTP 服务,让远程客户端也能连。
