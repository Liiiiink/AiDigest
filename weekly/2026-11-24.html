本周热点

产出翻倍,过审没翻倍——这周两份独立数据画出了同一个漏斗

哈佛的工作论文更新了:agent 让代码量涨 44%、PR 涨 35.7%,但「解决掉的问题」只涨 13.7%

  • 发生了什么:经济学家 Fiona Chen 和 James Stratton 的《Artificial Intelligence in the Firm: Bottlenecks in Software Production》更新版。数据来自 Jellyfish 的工程遥测加 GitHub 活动信号,覆盖 2021 年到 2026 年 3 月、约 3 亿条工作事件。核心拆解是:编码生产率 +73.7%,评审生产率 -7.0%;公司已经在重新分配人力——投在写代码上的精力降 22.7%,投在评审上的涨 43.4%;而工程师人数没有可观测的变化。八月那版里还有两个更扎人的数:PR 的评审耗时涨 49%,返工请求数量接近翻倍。
  • 凭什么算热点:样本量是本期最硬的一条——655 家公司、720,542 名工程师、约 3 亿条工作事件,不是 benchmark 也不是问卷。多源成立:另有一份 NBER 独立研究结论同向(自主 agent 让提交活动涨 240%,到真正发版时只剩 30%)。采用度口径有数:11-17 上 HN 首页 211 分(11-19 日报记录)。结构性是我收它的主因——它把「AI 提效」这件事从一个形容词变成了一个可定位的瓶颈坐标,而且论文自己给了反证据:到 2026 年 3 月,80% 的公司已经在用 AI code review 工具,但只有 23% 的评审意见是 AI 生成的,瓶颈在这些公司里照样存在,因为最终签字的还是人。
  • 你该不该动手:排进这个月,但动的不是工具,是你自己量一次这三个数。照论文的口径在你们团队上取:近半年的 PR 数、合入后 revert / hotfix 数、Jira 上真正 close 的 issue 数。如果 PR 涨了而第三个数没涨,你买再多 agent 席位都是在给第二个数加油。要提醒一句口径:核心数据截止到 2026 年 3 月,而 agent 能力在 2026 下半年明显上了一个台阶——所以这到底是「这代模型的局限」还是「人类评审产能的结构性天花板」,论文回答不了,你自己那三个数能回答。另外引用时注意标版本,八月版 LOC 是 +30%,十一月版是 +44%。

AI 扫描器已经是开源 CVE 的上游了:找到 29,439 个,真正修到上游的只有 516 个

  • 发生了什么:Anthropic OSS Scanner 的完整漏斗第一次公开。模型标出 29,439 个候选 → 报给维护者 6,157 个(覆盖 591 个项目,其中 5,103 个被确认)→ 截至 10-02,上游真正打上补丁的 516 个。占总发现量的 1.75%,占已上报量的 8.4%。Anthropic 自己也承认:报告不经人工验证直接发给维护者,其中 4,824 条是直接发出的、明说「可能含误报」;维护者反馈过严重性虚高、以及扫描器误解项目威胁模型的情况。
  • 凭什么算热点:持续性和多源在同一天凑齐了,这很少见——11-20 日报里的 Drupal 和 Ruby 两批高危,报告方都是这条流水线。Drupal 那条是 CVE-2026-132165 免认证 RCE(编号 ANT-2026-GMRPK0BU),Drupal 自评 Critical 18/25、PoC 已存在;Ruby 那批七个内存安全洞、五个带 PoC 能打到 RCE,报告方是 Ada Logics 的 Stephan Lipp 和 Anthropic。换句话说这不是一篇报道,是一条流水线的产出当天就落在两个你可能在用的东西上。结构性和上一条严丝合缝:1.75% 的转化率说明瓶颈已经从「发现」搬到了「分诊和修复」。
  • 你该不该动手:立刻试,而且这条有两个具体动作,一个今天做一个这个月做。今天的:升 Drupal 和 Ruby。Drupal 修复版本 10.6.22 / 11.3.22 / 11.4.13,11.2.x 及更早、10.5.x 及更早已脱离安全支持,没有补丁;来不及升就在 web server 配置或根 .htaccess 里封掉 /core/install.php(Apache Require all denied,nginx location = /core/install.php),同时确认 web server 进程不能写 settings.php——这是触发条件之一。Ruby 升到 4.0.10 / 3.4.13 / 3.3.14,并且别只查你自己装的那份,别的产品里捆绑的 Ruby 也要查。这个月的那个动作是判断题:「能找漏洞」正在飞快贬值,你要是在做安全方向,值钱的那一端已经换成了分诊、判断威胁模型、把补丁真正推到上游合并。顺带一句,这里面所有准确率数据均为 Anthropic 自述,无独立审计。

两家顶级团队,各自独立地给出了同一个答案:拿历史事故当 eval 去调你的验证器

Claude Code 团队公开了自己怎么验 AI 写的代码:90% 代码由 Claude 写,瓶颈早就不是生成

  • 发生了什么:Addy Osmani 11-16 发的一篇可以照抄的工程配置,不是方法论鸡汤。核心判断和上一组的数据完全对上:生成代码已经很便宜,「检查」才是你能把多少活交给 agent 的上限。能直接搬的几条:.claude/skills/ 里放一个 verify skill,让 Claude 像 QA 一样真的把应用跑起来;一份 39 条可靠性清单,但每次只跑与本次改动相关的 3~10 条;reviewer 的规则从 base 分支读 REVIEW.md,这样一个 PR 改不了评判自己的标准。卡点设计:开 PR 前先跑测试、构建、lint 这些便宜检查;连续失败 3 次就停下来交给人;commit gate 分 off / observe / enforce 三档,但连拦两次后放行第三次,免得 Claude 卡死。flaky test 不许跳过、不许加 sleep、不许重试到过为止。
  • 凭什么算热点:真人用过是这条的主证据——这是他们自己产线上跑着的配置,不是建议。采用度有数:HN 讨论 145 条评论(11-18 日报记录)。配套数字:同系列的 10-15 代码评审篇称 6 月到 9 月合入 PR 翻倍、revert 降超 40%,内部一个独立 grader 把结构化文件生成成功率提了最多 10 分。结构性在于他们怎么验「验证器」本身:拿历史事故和 revert 造正式 eval,把仓库还原到当时的状态,配一句话答案,只有正确描述了 bug 的发现才算分。Boris Cherny 的说法是「给 Claude 一个能自证的办法」是他的头号建议,估计效果差 2~3 倍。
  • 你该不该动手:立刻试,但只抄两条,别抄三十九条。第一条是 REVIEW.md 从 base 分支读——这是本周性价比最高的五分钟,因为它堵的是一个你多半没想过的洞:reviewer 的规则如果跟代码放在同一个分支里,agent 改规则比改代码容易。第二条是清单按 diff 裁剪,全量跑清单既贵又会把真问题淹在噪音里。至于那套 commit gate,先开 observe 档收两周数据再说,一上来 enforce 你只会收获一群绕过它的人。

OpenAI 公开 Performance Factory:让 Codex agent 自己查 ChatGPT 的性能回归,三个月 1,700+ 次调查

  • 发生了什么:11-19 发布。流程是性能告警触发开任务 → 派 agent 调查 → 记录结论 → 把修复方案交给工程师评审,人始终在审批位上,不是全自动合并。三个多月跑下来:1,700+ 次调查,600+ 次定位到根因,其中约 15 个修复是 Codex 原封不动的 PR 被合进去的。边界写得很明确:Codex 在「原因清晰、改动范围收得住」的场景最好用,复杂的还是人来。
  • 凭什么算热点:真人用过加产线数据——1,700 次调查跑在 ChatGPT 自己的性能告警流上。多源:OpenAI 官方博客和 VentureBeat 独家同日发。真正让我把它和上一条放进同一组的是结构性:他们做了个 perf-forensics skill,拿历史上真实发生过的回归当 eval 去调这个 skill,调到能「给一条告警、单轮返回一个诊断」为止;另外加了对抗式复核——不同轮次分别负责调查、质疑诊断、提修复。这和 Claude Code 团队「拿历史 revert 造 eval、只有正确描述 bug 才算分」是同一个方法,两家没商量过。
  • 你该不该动手:排进这个月,抄的是方法不是流水线。那三个数字要会读——1,700 次调查只换来约 15 个合入的 PR,成功率不到 1%,和这期第一组的漏斗是同一个形状。所以别把它理解成「agent 能修性能问题」,要理解成「agent 可以把 600 次根因定位的脏活干掉,省下的是人去看 1,700 条告警的时间」。真正可复制的只有一条:你手上任何一个 agent skill,只要你说不清它好不好用,就去历史里找十个已经发生过、已经知道答案的案例,把它们做成一个能打分的集合。没有这个集合,你调 prompt 就是在凭感觉掷骰子。

微软 agent-framework 被投毒:两个版本窃取 Azure / GitHub Actions 凭据,走的是官方发布账号

  • 发生了什么:11-17 晚间,恶意版本存活约 45 分钟。为什么这次比一般投毒更难躲:载荷不是藏在包的代码里等你 import,而是装了一个 .pth 启动钩子——Python 解释器每次启动都会执行 .pth,所以只要那个 venv / 容器 / CI runner 里跑了任何 Python 脚本,窃密就执行了。两个版本还都保留了对正常 agent-framework-core 1.26.0 的依赖,框架功能一切如常,不会报错。偷的东西:Azure CLI 数据、Azure DevOps agent 凭据、Git credential store、Docker 和 npm 配置、.env 文件,还会主动去换一份新的 Azure 托管身份 token 和 Azure DevOps token,外带到一个 webhook[.]site 端点。1.26.2 比 1.26.1 还多抓了 GitHub Actions OIDC token。
  • 凭什么算热点:多源是本期最硬的一条,没有之一——Aikido / Chainguard / Endor Labs / OX Security / SafeDep / Socket / StepSecurity / Wiz 八家独立报告。采用度:该包月下载约 190,000 次。强制性不用解释:中了就得轮换云凭据。值得单独说一句的是热度和影响面的背离:HN 讨论只有 13 分——这件事的社区关注度明显低于它的实际杀伤力,这正是周报该干的活。
  • 你该不该动手:立刻试,三步,顺序不能换。① 排查窗口是 11-17 20:35–21:20 UTC——这段时间内有没有机器装过 agent-framework 1.26.1 或 1.26.2。② 重建受影响的镜像和 runner,而不是原地卸载——.pth 可能已经跑过了,卸载包不等于清掉后果。③ 轮换 Azure / Azure DevOps / GitHub 凭据,然后 pip install agent-framework==1.26.0 钉死。另外有一条能自动化的通用检查值得现在就加进你的依赖门禁:这两个恶意 wheel 都没有 trusted publishing 来源证明。根因目前各家说法不一致——Wiz 倾向于微软 ESRP 签名发布管线的客户端证书和私钥被窃(工具链自称 Cairn),SafeDep 发现一个当天新建、却对该包及另外 5 个项目有发布权限的维护者账号 vibiret。不管哪个对,结论一样:「它是官方账号发的」已经不是一条安全保证了。

Java4Shell(CVE-2026-114938):Base64 解码越界写 62 字节,免认证 RCE,JDK 17.0.6 之后全中

  • 发生了什么:OpenJDK 用一段手写汇编拿 AVX-512 加速 Base64 解码,一个很短的畸形输入会在 Java 把它判为非法之前,先往缓冲区尾部外写 62 字节(Oligo 描述为整数下溢)。Calif 的 Quang Luong 发现,并演示了在 Jira、Confluence、Jenkins、Keycloak 上的免认证 RCE。三个条件同时成立才中:① JDK ≥ 17.0.6(2023 年 1 月起,含 21 / 25 / 27,任何厂商构建——Corretto、Temurin、Microsoft OpenJDK、Zulu、Red Hat OpenJDK 都算);② CPU 带 AVX-512 VBMI 的 x86-64(Intel Xeon Ice Lake~Granite Rapids、AMD EPYC Zen 4+);③ 跑的是 HotSpot。17.0.6 以前的版本、标准 OpenJDK 8 和 11、ARM64、OpenJ9、Azul Prime/Zing 不受影响;java.util.Base64 的 MIME 解码器走标量路径,也不受影响。
  • 凭什么算热点:强制性顶格——CVSS 4.0 Calif 评 9.2 / CVSS 3.1 Oracle 评 8.1,免认证 RCE,Oracle 11-17 CSPU 同批修了 655 个漏洞。多源:Wiz、Oligo、Calif 三家各出技术分析,配 HN 讨论串。和上一条放在同一组,是因为它们的共性比各自的细节更值得记:一个是 .pth 让你「没 import 也中」,一个是 JVM intrinsic 让你「没写过一行不安全代码也中」——两处都在你没选过的那层。
  • 你该不该动手:立刻试,今天就做,而且这条有个比打补丁更快的止血点。升到 17.0.21.0.3 / 21.0.13.0.3 / 25.0.5.0.3 / 27.0.1.0.3;暂时不能升就加 JVM 参数 -XX:-UseBASE64Intrinsics——影响面最小,代价只是 Base64 变慢,可以用 JAVA_TOOL_OPTIONS 批量下发,打完补丁记得撤掉。更窄的写法是 -XX:+UnlockDiagnosticVMOptions -XX:DisableIntrinsic=_base64_decodeBlock。别用 -XX:UseAVX=2:它也能挡,但会关掉全部 AVX-512 拖慢其他计算,而且在 ARM 上会直接起不来。排查顺序按暴露面来:Keycloak、Jira、Confluence、Artifactory、Jenkins、PingFederate 这批对外的先过一遍。截至 11-17 无在野利用报告、未进 CISA KEV——但这条别当成可以拖的理由,PoC 的构造在公开分析里已经讲得很清楚了。

  • Windows 11 在统计你用哪个 coding agent(9 个进程名写死在 MissionControlAggregator.dll 里,HN 636 分) — 本周采用度最高的一条,明确不收。 HN 636 分(11-18 记录)是实打实的,但它对你没有任何动作:Win11 家庭版关不干净遥测,公司电脑上这个设置多半也不归你管。而且研究者自己证明了这份数据不可靠——纯按文件名匹配,把 cmd.exe 改名成 codex.exe,Windows 就认定你用了 Codex;他用公开 ISO 装的基线虚拟机上这个功能还是关的,所以连「每台机器都在传」都不能说。唯一值得记一笔的是方向:Segments.Cohorts 目前上报的群体标签只有一个 IsDeveloper,「开发者在用哪家 agent」正在被平台方当成市场数据采集。等它出现在一份公开的微软市场份额报告里,那才是故事。
  • Claude-BugHunter(11-18 单日 +1,005 star、GitHub Trending 第一,83 个安全 skill)+ NVIDIA SkillEvaluator(11-17 单日 +873 star) — star 速度完全够采用度,但这是连续第四期出现「又一批给 agent 装的技能包」,两条的硬伤也照旧:BugHunter 本质是一大包 markdown,没有任何第三方实测说它真挖到了什么(而且只能在你有授权的 bug bounty / 红队范围内用);SkillEvaluator 的 Tier 3 要 provider key + agent CLI + 沙箱,门槛不低。SkillEvaluator 的 Tier 1 倒是不用等我——skillevaluator validate ./my-skill --tiers 1 是纯确定性检查、不要 API key、能出 SARIF 喂 GitHub Code Scanning,写 skill 的今天就挂上 CI。这是个待办不是判断题。
  • Gemini API 上线 Tool Retrieval / defer_loading(闲置工具只占约 26 token,不额外收费) — 这条我犹豫最久。结构性是成立的:几百个工具不再全量塞上下文,模型仍看得到名字和描述、参数 schema 用到才加载,对接 MCP 尤其划算(给 mcp_server 设 defer_loading: true 会把这台 server 的所有工具一起 defer)。不收的理由是绑死一家且还在预览:只支持 Gemini 3.6 及以后、必须走 v1beta 的 Interactions API(generateContent 不支持)、每个请求只准一个 tool_search。MCP 工具已经多到撑爆上下文的人今天就可以试,不用等我分析——一个请求加一个工具、给不常用的挂 defer_loading,两步的事。等它进稳定版、或等 Anthropic / OpenAI 跟进同一形态,这件事才算「这类工具的玩法变了」。
  • Perplexity Orchestrator(45+ 模型一把 key,不收路由费) — 形态确实对上了一个真痛点:失败重试换的是「同一个模型的另一个部署」而不是偷偷换成别的模型(比如把 Claude 请求从 Anthropic 切到 AWS Bedrock),接入只改 key、base URL 和模型 ID。不收是因为只有官方单源、零采用度数字:官方说 10-04 至 11-02 期间成功率高于任一单一供应商,没有第三方复核;45+ 还是 85+ 模型两个来源口径都不一致。等有人贴出切换前后的成功率对照。
  • OpenCode Browse(让 agent 用你那个已登录的浏览器) — 想法是对的(Playwright MCP 另起干净 profile,你的登录态、2FA、扩展全没了),但单源、无采用数字,而且它自己标明了权限边界:扩展用 chrome.debugger 执行命令,agent 拿到的是你浏览器的全部权限。等有人贴实测,或者等一个把权限收窄到单标签页的版本。想现在用的至少把「限定白名单站点」那个开关打开。
  • StarSling(给「agent 刷 PR」的仓库做会自我优化的 CI)/ Replit Missions(按预算买 agent 集群产出)/ Mistral Vibe 欧洲免费三个月 — 三条一起不收,理由同一个:全是厂商自述或促销,没有一条有第三方数字。StarSling 的加速样本(gogs 12.8x、shellcheck 5.5x)是官方给的,HN 评论区自己就在问测试稳定性和自动改动的边界;Replit 那 13 个 NumPy 任务的加速曲线也是自测,而且收益主要来自前 16 个 agent;Mistral 的码一小时就发完了,Vibe + Le Chonk「最强开源组合」的说法没有任何第三方验证。StarSling 那个想法——「一个给 agent 开的 PR 提速 CI 的 agent」——和本期主线其实是同一个母题,等它有第三方实测再说。

动手教程:用你仓库里的 revert 历史,造一把能给「AI 审查」打分的尺子

本周第二组热点的落地版:一个下午,你会拿到一个 10 条的回归 eval,以后每次改评审规则都能量出来变好还是变坏

你将做出:一个属于你这个仓库的评审 eval 集——10 个历史上真的漏网、真的被 revert 过的 bug,每个配一句话标准答案和一个可打分的 diff。做完你调 review prompt 不再是凭感觉,是能看着 命中 4/10 → 7/10 做决定。

准备:

  • 一个至少有一年历史、能找到 revert 或 hotfix 记录的仓库。你主力维护的那个。
  • git,和任意一个你现在正在用的 AI 评审入口——/code-review、CI 上挂的 AI reviewer、或者干脆就是手动把 diff 贴给模型。用哪个不重要,重要的是整个过程里只换一个变量。
  • 两小时不被打断的时间。第 2 步占掉其中一大半,没有捷径。

跟着做:

  1. 先把候选捞出来,这步用 git 不用脑子。 git log --oneline --grep='^Revert' --grep='revert:' --grep='hotfix' -i -n 200。再补一条找修复型提交:git log --oneline --grep='fix:' -i -n 200。你会拿到几十上百条,先别筛。
  2. 筛出 10 个「真 bug」,这步全是人工判断,也是整件事的价值所在。 一条一条看,只留「当时合进去了、后来发现是错的、然后被回滚或热修」的。要明确排除三类:改需求回滚的、回滚实验性功能的、纯格式/依赖升级的。对留下的每一条,记三样东西到一个文件里:(a) 引入 bug 的那个 commit SHA;(b) 那个 commit 的 diff(git show <sha> 存下来,这就是你的「待审 PR」);(c) 一句话标准答案——这个 bug 到底是什么、会在什么条件下出事。这个「一句话答案」就是打分依据,照 Claude Code 团队的口径:只有正确描述了 bug 才算分,「这里变量名不好」「建议加个注释」一律不算。
  3. 跑基线,记两个数。 把 10 个 diff 逐个喂给你现在的评审入口,只给 diff,别给答案,也别暗示有 bug。每跑一个,对照第 2 步的标准答案打一个 0 或 1。记:命中数 N/10,以及每次的 token 消耗(从 API usage 字段取,别估)。跑完你大概率会有点难受——这是对的,你第一次知道了你的评审网眼有多大。
  4. 只改一处,再跑同一批。 挑本周 Claude Code 团队那两条里最便宜的一条先改:把你的评审规则抽成一个 REVIEW.md,并且让 reviewer 从 base 分支读它(CI 里就是 git show origin/main:REVIEW.md,别读工作区的那份)。这条堵的是「PR 能改评判自己的标准」这个洞。改完用同一批 10 个 diff 重跑,对比 N 和 token。然后再试第二处:清单别全量跑,按 diff 命中的文件类型只跑相关的 3~10 条——看命中数掉没掉、token 省了多少。
  5. 把尺子留下,顺手接上两道闸。 把这 10 条连同答案 commit 进仓库(建议放 evals/review/),以后任何人想改评审 prompt,先拿这 10 条跑一遍。另外抄两条便宜的卡点:agent 连续失败 3 次就停下来交给人;flaky test 不许靠重试、加 sleep 糊弄过去——后面这条不是洁癖,它防的是你把「失败了再跑一次就行」教给 agent。
做完你会:有一个能复现的分数,以及一个更值钱的副产品——第 2 步那 10 条标准答案,本身就是你这个仓库最容易出事的地方的清单。拿它去对照你的测试覆盖,大概率能发现其中三四条根本没有对应的测试。下一步:每季度往里补 3 条新的 revert,让这把尺子跟着仓库一起长。
