模型精讲:KV Cache(键值缓存)——大模型吐字快慢的头号功臣

同样的模型、同样的显卡,开不开 KV Cache 速度能差 5 倍——它是推理优化里性价比最高的一招

核心看点:大模型每吐一个字都要"重读"一遍前文,KV Cache 就是那本记好的笔记,让它不用从头再读。

它是什么

大模型生成文字是逐个 token 往外蹦的,蹦完一个,把它接到句子末尾,再蹦下一个。

问题在于:每蹦一个新 token,模型默认会把整句话从头到尾重新算一遍注意力。生成 "Time flies fast" 时,"Time" 和 "flies" 的中间结果被反复计算了好几次——可它们根本没变。

KV Cache 就是把这些算过、且不会再变的中间结果(注意力里的 Key 和 Value 向量)存下来,下次直接取用。

为什么重要

一句话:它把生成的计算量从"平方级"压到了"线性级"。

  • 不开缓存:生成 n 个 token,累计计算量是 O(n²)——文章越长,每个新字越慢,体感上就是"越写越卡"
  • 开了缓存:每个 K/V 只算一次,之后复用,每步的计算量是 O(n)

Raschka 在 Mac Mini M4(纯 CPU)上用 1.24 亿参数的小模型生成 200 个 token,给出了实测数据:

| 实现方式 | 耗时 | |---|---| | 不用缓存 | ~3.53 秒 | | KV Cache(torch.cat 版) | ~0.72 秒 | | KV Cache(预分配版) | ~0.71 秒 |

约 5 倍加速。你今天用的所有在线大模型服务,底下几乎都开着它。

它是怎么工作的:一本会自动续写的笔记本

想象你在读一本长篇小说,每读到新一页都要回答"这页跟前文什么关系"。

  • 笨办法:每翻一页,把前面所有页从头再读一遍——这就是不开缓存
  • 聪明办法:边读边在旁边记笔记(每页的要点)。翻到新一页时,只需要读这一页 + 瞄一眼笔记本

KV Cache 就是那本笔记本。具体三步:

  1. 首次填充:模型把输入的所有 token 的 K/V 向量算出来,存进缓存
  2. 增量计算:每来一个新 token,只算它自己的 K/V 向量
  3. 拼接复用:把新算的 K/V 接到缓存后面(代码里就是一次 torch.cat),拿完整的 K/V 去做注意力

代码层面,改动集中在三个类:MultiHeadAttention 里注册 cache_k / cache_v 两个缓冲区;TransformerBlock 把 use_cache 开关往下传;GPTModel 加一个位置计数器 current_pos。

进阶点 1:位置计数器不能省。 新 token 只有知道自己排第几,位置编码才算得对。少了 current_pos,新 token 会被当成"覆盖了之前某个位置",位置信息直接错乱,输出变成乱码。 🔍 进阶点 2:速度是拿显存换的。 缓存随 token 数线性增长,长上下文 + 大模型时会吃掉惊人的显存。所以业界又衍生出一堆省显存的招:预分配张量(按最大长度一次性开好,避免反复 torch.cat 造成内存碎片)、滑动窗口缓存(只保留最近 N 个 token)。Raschka 提到,给 Qwen3 0.6B 这类模型按 131k 上下文预分配,光缓存就要多吃 约 8 GB 显存——所以他反而退回用 torch.cat。

什么时候它反而没用

两个容易踩的认知误区:

  • 训练时用不上。训练是整段并行算的,不存在"逐个吐字",没有可复用的历史
  • 小模型 + GPU 上收益有限。原文实测,小模型在 GPU 上跑,torch.compile 编译过的普通版反而更快——因为模型太小,张量搬运的开销盖过了缓存省下的计算

动手教程:20 行代码做一个"听得懂人话"的搜索

用 sentence-transformers 搭一个语义搜索:搜"神经网络怎么工作",它能找出讲深度学习的那段——哪怕一个字都没重合

你将做出:一个纯本地运行的语义搜索脚本,输入一句话,从你自己的文档库里找出意思最接近的几条。

准备:

  • Python 3.10+、PyTorch 2.2+(官方推荐版本)
  • 一条能访问 Hugging Face 的网络(首次会下载模型,all-MiniLM-L6-v2 只有几十 MB,CPU 就能跑,不需要显卡)
  • 装依赖:pip install -U sentence-transformers

跟着做:

  1. 先跑通"相似度"这个概念。 新建 demo.py,把三句话变成向量,看看模型觉得谁跟谁像:
   from sentence_transformers import SentenceTransformer

   model = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2")

   sentences = [
       "The weather is lovely today.",
       "It's so sunny outside!",
       "He drove to the stadium.",
   ]
   embeddings = model.encode(sentences)
   print(embeddings.shape)          # [3, 384] —— 每句话变成一个 384 维向量

   print(model.similarity(embeddings, embeddings))

跑完看输出:前两句(都在说天气好)相似度约 0.66,第三句(开车去球场)跟它们只有约 0.10。模型没做任何关键词匹配——"lovely" 和 "sunny" 一个字都不重合,但它知道这俩是一个意思。

  1. 换成你自己的文档库,做真正的搜索。 把 corpus 换成你的笔记、FAQ、产品文档,每条一句话或一小段:
   import torch
   from sentence_transformers import SentenceTransformer

   embedder = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2")

   corpus = [
       "Machine learning is a field of study that gives computers the ability to learn.",
       "Deep learning is part of a broader family of machine learning methods.",
       "A man is eating pasta.",
       "The girl is carrying a baby.",
   ]
   # 文档侧用 encode_document,查询侧用 encode_query —— 注意这两个是分开的
   corpus_embeddings = embedder.encode_document(corpus, convert_to_tensor=True)

   query = "How do artificial neural networks work?"
   query_embedding = embedder.encode_query(query, convert_to_tensor=True)

   scores = embedder.similarity(query_embedding, corpus_embeddings)[0]
   top_scores, top_ids = torch.topk(scores, k=min(3, len(corpus)))
   for score, idx in zip(top_scores, top_ids):
       print(f"{score:.4f}\t{corpus[idx]}")

查询里没有 "deep learning" 这个词,但讲深度学习那条会排到前面。

  1. 文档变多了,换成官方的 semantic_search。 上面那种手写 topk 在几千条时还行,再多就该用官方封装了——它会自动分块、并行:
   from sentence_transformers.util import semantic_search

   hits = semantic_search(query_embedding, corpus_embeddings, top_k=5)[0]
   for hit in hits:
       print(f"{hit['score']:.4f}\t{corpus[hit['corpus_id']]}")
一个容易搞错的点:选模型要分清对称还是非对称搜索。查询和文档长度差不多(比如"找相似问题")是对称,用 all-MiniLM-L6-v2 这类通用模型就好;如果是短问题去找长段落(典型的 RAG 场景),那是非对称,应该换 MS MARCO 系列模型,效果差别很明显。
做完你会:亲手体会到「向量 = 语义的坐标」这件事——这正是当下所有 RAG、知识库问答系统的地基。 下一步可以探索三个方向: - 加一层重排(rerank):先用当前的双塔模型(Bi-Encoder)快速捞出 top 50,再用 Cross-Encoder(如 cross-encoder/stsb-distilroberta-base)精排前几名。慢一些,但准得多,这是工业级 RAG 的标准两段式做法 - 上百万级文档:精确检索会变慢,该换 FAISS / hnswlib 这类近似最近邻(ANN)索引,拿一点点召回率换几十倍速度 - 搜图片:换成 Qwen/Qwen3-VL-Embedding-2B,图和文字会被编码进同一个向量空间,可以直接用文字搜图
