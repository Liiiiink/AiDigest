打的不再是你的依赖,是你写代码用的那套工具

Wiz「Black October」:九家 AI 开发平台一个月内接连失守,全冲着环境变量来

  • 发生了什么:Fireworks AI(10-06)、Andromeda(10-09)、Zeabur(10-14)、Lightning AI(10-15)、OpenCode(10-16~17)、Railway(10-20)、Warp(10-23)、CommandCode(10-28)、Northflank(10-30)——九起事件根因各不相同(凭据泄露、构建基础设施提权、第三方供应商、遗留系统),但所有公开报告的共同点只有一个:攻击者精准地翻存储的环境变量,尤其是能调 AI 的那些。Zeabur 因为这次直接宣布关停。
  • 凭什么算热点:持续性和多源都有——10-30 日报记 LiteLLM、10-31 记 Cursor 扩展投毒、11-02 Wiz 把它们并进同一张名单,同一条线被本周三份日报接力提到;Wiz 原文由 BleepingComputer / Axios 同步报道。可验证的量级:Wiz 跟踪的两起 Bedrock 滥用,A 案 30 小时约 80 万次调用、B 案 13 小时约 170 万次,两起合计按标价算超过 10 万美元。从凭据被拿到到第一次非授权调用只隔约 30 分钟——一个住宅 IP 在一分钟内横扫多个组织试 key。
  • 你该不该动手:立刻试,而且今天就有两件具体的事。一是对名单——这九家里你用过哪家,去签发方轮换该平台上存过的 key(只改平台上那一份没用)。二是抄那条配置:给 Bedrock key 的 IAM 策略限定区域推理配置,B 案正是因为策略只允许 us.*、被区域配额挡下了大半损失,而 A 案走 global.* 只有约 6% 被限流——在这里限流是止损器,不是性能问题。

Cursor 扩展市场里的 Claude Code 扩展被投毒,卸载扩展清不掉后门

  • 发生了什么:10 月 29 日太平洋时间约 02:27~13:35,一个顶着合法 anthropic.claude-code 标识、版本号 2.1.313 的恶意构建挂在 Cursor 扩展市场上,约 11 小时,最多 5000 名开发者受影响。这不是仿冒包——Cursor 说问题出在自己的市场代理环节,不是 Anthropic 的构建发布系统。恶意代码 66 行,往 authorized_keys 塞攻击者公钥、起本地 SSH 服务打反向隧道、写持久化。
  • 凭什么算热点:多源够硬——Cursor 官方安全通告 + 微软安全响应中心 10-30 的深度分析 + Sophos / StepSecurity / OX Security 同步跟进,HN 10-31 在榜;而且 11-02 的 Black October 汇总把它收进了同一条线,持续性成立。强制性更直接:卸载扩展不等于清除,SSH key、LaunchAgent、隧道进程都得手工删。
  • 你该不该动手:立刻试——只要你这台机器装过 Cursor,这是五分钟的事。IoC 照着查:扩展目录 anthropic.claude-code-2.1.313-darwin-arm64(或 -win32-x64),里面的 extension.js 含 IP 134.209.82.225 和字符串 svc-telemetry;macOS 上另查 LaunchAgent com.apple.sysmond.plist 和隐藏脚本 ~/.config/.smt。命中了就手工清三处再轮换这台机器能摸到的全部凭据。没中招的范围也记清楚:微软官方 VS Code 市场、终端版 Claude Code、npm 上的 @anthropic-ai/claude-code 都不受影响——别过度反应。

EMBRACE:五个 AI 编码工具的内置浏览器被成套攻破

  • 发生了什么:10 月 29 日公开,覆盖 Cursor、GitHub Copilot、OpenAI Codex、VS Code、Claude Desktop。根因是同一个:这些内置浏览器由 AI 驱动而不是人在点,厂商为了让 AI 能预览项目、读标签页内容,普遍放松了独立浏览器该有的沙箱边界,于是内置浏览器继承了宿主级别的文件访问权限。后果分三种:Cursor 是代码执行(恶意页面往命令编排框注入隐藏指令,实测把助手骗着弹了计算器)、Copilot 是地址栏欺骗(显示 github.com/login,渲染的是攻击者页面)、Codex / VS Code / Claude Desktop 是一个本地文件读全盘。
  • 凭什么算热点:结构性——研究者 Gal Weizman 给这类问题起了名(EMbedded BRowser, trusted like a real one),这不是某家的 bug,是「为了让 AI 用浏览器而拆掉沙箱」这个做法的系统性后果,五家同时中招本身就是证据。多源:Forever Security 原文 + Help Net Security / Hackread / daily.dev 同日跟进。强制性:截至 10 月 29 日,微软和 OpenAI 都还没发修复(Cursor 10-01 已静默修,Copilot 的欺骗修复在 build 1.1.29)。我这边这周没能拿到更新的补丁状态,按未修处理。
  • 你该不该动手:立刻试,但「动手」只有一个动作,一秒钟:别点 agent 丢给你的本地 HTML 预览链接。整条利用链的前提就是开发者点了助手生成的指向本地恶意 HTML 的那个链接。另外记住边界:终端里的 Claude Code 没有内置浏览器,不在测试范围内——这周值得你把浏览器预览这类活从桌面壳子挪回终端。顺带记一条:既然不点 Trust 根本用不了这些工具,那个信任提示在实践中等于不存在,别拿它当防线。

agent 写得越来越多,瓶颈整个压到了审查侧

GitHub Octoverse 2026:9 月 40% 以上的 PR 由 agent 起草,合入率已经反超人类

  • 发生了什么:统计区间 2025-10-01 至 2026-09-30。agent 起草的 PR 占比从 3 月的 17% 涨到 9 月的 40% 以上,9 月单月 1.1 亿个 agent PR,约是 3 月的六倍。质量线更关键:agent 参与的 PR 两周内合入率从 2 月的 83% 升到 9 月的 90%,已经高于无 agent 参与的 86%;但 agent 起草的 PR 平均触及更多文件(约 87% vs 79%)。
  • 凭什么算热点:GitHub 官方报告,Visual Studio Magazine / developer-tech / GitGuardian 同日跟进,多源成立。结构性也成立:这是第一次有平台级数据把「瓶颈挪到审查侧」从感觉变成数字——写的量涨了六倍,每个 PR 还摸更多文件,而评审人数没变。本周 GitHub 自己在同一天上线多模型深度 code review,不是巧合。
  • 你该不该动手:排进这个月,要动的不是工具是指标。去看你团队的两个数:agent 参与的 PR 占比、以及 PR 平均触及文件数的同比。如果第二个数在涨而你的评审流程一个字没改,你现在就在亏——不是亏质量,是亏 reviewer 的注意力。另外有条选型信号值得单独记:9 月手动选模型的 Copilot 用户里 61% 用了不止一个模型(四个月前 50%),付费套餐里被用到的模型有 47 个,没有任何单一模型超过请求量的 25%——「只精通一家模型」正在变成劣势。口径提醒:这个数只统计「起草」不代表质量,且 GitHub 用新定义重算了往年数据,和旧版 Octoverse 不能直接对比。

GitHub Copilot code review 加 Max 档:多家模型各自独审,再由聚合 agent 合成一份

  • 发生了什么:10-28 进 public preview,Lite / Balanced 之上多了第三档。Max 跑多个互相独立的 review agent、分别用不同厂商的模型,再用一个聚合 agent 把各家发现对账合并。代价明说了:更慢、更费 credits。配置粒度到单个 PR / 仓库 / 组织 / 企业,管理员能设上限防止有人全开烧光额度。
  • 凭什么算热点:不是「又一个 review 工具」,是上周那条线的续章并且换了形态——上期我收的是 Cloudflare security-audit skill(「查证的 Agent 绝不是发现问题的那个 Agent」)和 impeccable 的确定性规则,当时的结论是「抄做法,不用装东西」;一周之后厂商直接把多模型独审 + 聚合做成了产品档位。配合 Octoverse 同日发布的 40% 数字,这是「社区做法 → 平台能力」的完整一跳。
  • 你该不该动手:排进这个月,但先别开 Max。GitHub 宣称 Max 在 ReviewBench 高危问题上拿到最高 F1,但没公布这个分数本身——当营销看待。真正该做的是自己标定一次:在你自己的仓库上手搓一遍多模型独审 + 聚合(本期末尾的教程就是这个,不花 Copilot credits),量出两个模型的发现重叠率。重叠率高就说明第二个模型是白花钱。顺带两件同批上线的事:Copilot approvals 转正式可用——要不要让它算进分支保护规则,这个自己权衡,别默认开;Copilot Fusion(自动模型路由)GA,但 GitHub 不公开池子里有哪些模型。

Project Zero 实测:AI agent 挖洞已追平顶级 fuzzer,但找到的是完全不同的两批 bug

  • 发生了什么:六个月 V8 实战,BigSleep 找到 45 个、Fuzzilli 找到 37 个,重叠只有约 25%。分工清楚:AI 赢在需要多步推理和「魔法值」的洞(比如 bytecode handler 表在 >256MB 时的整数截断)、以及 fuzzer 语法还不支持的新特性;fuzzer 赢在跨优化 pass 交互产生的非局部 bug、和 C++ 编译器优化导致的问题——这类「看源码推不出来」的洞 AI 也看不出来。
  • 凭什么算热点:这是本周「真人用过」证据最硬的一条——不是博客感想,是 Google Project Zero 自己拿半年和两套真实工具在 V8 上跑出来的对照数据,Lobsters 当日上榜。还有一个回溯实验:让 BigSleep 从单个起始 commit 去找 2023–2026 年的 112 个历史 Fuzzilli bug,复现率约 62%,换提示词和起点后升到约 70%,且没检测到对训练截止前 bug 的记忆效应。结构性在于它给出了一条反直觉结论:fuzzer 难找的 bug,AI 大概率也难找——难度是 bug 本身的属性,不是方法的属性。
  • 你该不该动手:不关你事,但那个 25% 要记住。除非你在做引擎级安全研究,否则这篇没有你能装的东西。它的价值是给上面两条当尺子:25% 这个重叠率就是「多模型/多方法并跑」的收益上限参照——如果你跑两个审查器出来的发现几乎完全重合,那不是两个审查器,是一个审查器跑了两遍。别把「AI 取代 fuzzer」或「多开几个 agent 就更安全」当成默认假设。

effort 这个旋钮,今年最该被标定一次

FrontierCode 2.0:按「维护者愿不愿意合这个 PR」打分,最强模型只得 45.5%

  • 发生了什么:Cognition(Devin 团队)出的 132 道题,判定标准是开源维护者的合入意愿,每题由维护者花 40 小时以上构造。榜单:Opus 5.5 45.5%、GPT-6 Astra 42.8%、Sonnet 5.5 41.0%、GPT-6.1 Sol 39.0%、Fable 5.1 32.4%;每题成本 Opus 5.5 $12.82、GPT-6 Astra $6.68、GPT-6.1 Sol $1.03。比 1.1 难在「周全性」阻断检查从 168 条涨到 501 条。
  • 凭什么算热点:我收的不是这个榜单,是榜单里那一个调参结论——把推理 effort 拉满,周全性检查失败率从 26.0% 降到 15.3%,但越界改动(scope check)失败率从 3.8% 升到 4.9%。也就是说 effort 不是单调变好,它在「做全」和「少动」之间换挡。这条有两份日报的交叉佐证:10-29 同日的 Artificial Analysis Index v5 给了成本那一侧的同一个权衡——Opus 5.5 低 effort 得 35 分、每题 $0.98,拉满得 58 分、每题 $10.04,十倍价钱买 23 分;10-27 的 GPT-6.1 Terra 则把便宜档整体抬了一级(Terminal-Bench 4.0 从 21.5% 到 50.3%,$1/$5/$0.05,比上一代便宜一半,HN 567 分 / 353 评论)。三条独立来源指向同一个动作。
  • 你该不该动手:立刻试,而且这是本周最省钱的半小时。拿你自己流水线上跑量最大的那类任务,分别用低 / 中 / 高 effort 各跑十次,记两个数:成本,和你实际要返工的比例。大概率你会发现其中一档之后收益就平了——AA 的数字是十倍价钱买 23 分,你自己那条曲线的拐点在哪,只有你量得出来。两条具体的调法:改动范围敏感的活(重构、线上热修)别无脑拉满 effort,越界风险是真的在涨;跑量大的日常活去试 GPT-6.1 Terra 这一档,但官方自己说最复杂的编码活还是该用 Sol 或 Astra,别全局切换。另外记住 FrontierCode 的 45.5% 不是通过率,是按阻断项加权、漏一项即零分的分。

动手教程:在你自己的仓库上标定一次「多模型独立审查」到底值不值

手搓一遍 Copilot Max 的做法,不花一分 Copilot credits,量出重叠率再决定要不要买

你将做出:一组可复用的审查脚本,和一个只属于你这个仓库的数字——两个不同厂商的模型审同一份 diff,发现的重叠率是多少。重叠率告诉你第二个模型是在捞新东西,还是在重复第一个。

准备:

  • 一个有真实改动的分支(用真实改动,别用玩具代码——玩具代码上两个模型会给出几乎一样的结果,量不出差异)
  • 两个不同厂商的 CLI:Claude Code / Codex CLI / Gemini CLI 里任选两个。同厂商的两个模型不算,独立性是这件事的全部价值
  • 不需要 Copilot Max、不需要新装任何东西

跟着做:

  1. 先把被审对象钉死。两个审查器必须看同一份输入,否则它们各自在仓库里乱逛,看到的东西都不一样,后面的对账就没有意义:
    ```bash
    mkdir -p /tmp/review && cd /tmp/review
    git -C /path/to/repo diff main...HEAD > diff.patch
    wc -l diff.patch # 几百行最合适;上千行先拆
    ```
  2. 写一份共用提示词,强制分级输出。这里抄的是 Cloudflare security-audit skill 的三档结论,也正是 Copilot Max 的聚合 agent 要对账的东西。把下面这段存成 prompt.md:
    ```
    审查附带的 diff。只输出 JSON 数组,每项:
    { "file": "", "line": 0, "claim": "一句话说明缺陷",
    "level": "confirmed | needs_validation",
    "missing_fact": "仅当 level=needs_validation:写明到底哪个事实你没查实",
    "severity": "仅当 level=confirmed 时才填" }
    规则:没有完整源码链路支撑的,一律 needs_validation,且不许给 severity。
    风格问题、命名问题不要报。
    ```
    最后两条规则是重点:不许给未查实的问题标严重性,否则两份结果没法对账——你分不清「A 说高危」和「A 猜高危」。
  3. 两个厂商各跑一遍,互相看不见对方。这是 Max 档的核心,也是最容易做错的一步——千万别把 A 的结果喂给 B 让它「补充」,B 会被 A 说服,你拿到的就是一份结果的两个副本:
    ```bash
    # 各自开全新会话,只给 prompt.md + diff.patch
    # 输出分别存 a.json / b.json
    ```
  4. 第三次调用做聚合。开第三个全新会话,只给它 a.json、b.json 和 diff.patch,任务是对账而不是重审:两边都报的升一级;只有一边报的降到 needs_validation 并写明「另一边为什么没报」;互相矛盾的单独列出来给人看。
  5. 算那三个数,然后做决定:
    ```bash
    # 两边都报的(交集)、只有一边报的、总 token 花费
    ```
    参照系是本期 Project Zero 那个 25%:AI agent 和顶级 fuzzer 在 V8 上跑半年,重叠只有约四分之一。你的两个模型如果重叠率接近 100%,第二个模型就是在白花钱,换一个差异更大的厂商再测一次;如果落在 20~50% 区间,说明它们确实在捞不同的东西,这笔钱花得值,可以考虑直接上 Copilot Max 省掉手工聚合。
做完你会:手上有一个数字,而不是一个感觉——下次有人问「要不要开多模型审查」,你答得出来。下一步有两条:把第 2 步那份提示词包成一个 skill 让 agent 自己跑;或者把重叠率作为常规指标,每月量一次——模型在变,这个数也会变。
