  1. 🆕 《工具调用的苦涩教训》:让模型写 Python 调工具,比让它填 JSON 更强 — 标题致敬 Sutton 那篇著名的《苦涩教训》,论点也一脉相承:别给模型搭专用脚手架,把通用计算交给它。当前主流的工具调用是让模型输出一段结构化 JSON,由框架解析后执行;论文主张的编程式工具调用(PTC)则把工具直接呈现为带类型的 Python 函数签名,让模型写代码去调,执行和取回结果都在同一个 Agent 轮次内完成。在 BFCL v4 上跨 14 个模型对比:PTC 在 11/14 个模型上打平或胜过原生 JSON 调用,GPT-5.6 系列提升 10.6%;需要并发扇出(一次调多个工具)时,13/14 个模型上 PTC 不落下风;而在上下文腐坏(context rot,长上下文里信息质量退化)的条件下,JSON 基线平均掉 2.3%,PTC 基本不掉。而且模型越强,PTC 的优势越明显。
    为什么值得关注:这是今日主线在论文层面最干净的一个证明——同一个模型,只是换了工具的呈现方式,分数就动了 10%。而「模型越强、通用方案越占优」这个趋势线,基本判了各种花式 JSON schema 工程的死刑。

  2. AgentOPSD:不用 critic、不用额外采样,给 Agent 的每一步单独记功 — HF Papers 今日第一(75 赞)。长程多轮 Agent 训练的老大难是功劳分配:任务成功与否是一个总分,但真正决定成败的往往只有其中几步关键决策,轨迹级的优势估计根本分不清谁该记功。AgentOPSD 的做法是把 token 级的师生对数概率差聚合成轮次级证据,再在对数几率空间里递归更新一个贝叶斯信念状态,通过相邻状态之间的边际信念修正来识别「关键轮次」,从而把稀疏的结果监督转成稠密的轮次级信号。工程上很轻——既不需要额外的 critic 网络,也不需要多跑 rollout。在 ALFWorld、WebShop、Search-QA 上以 Qwen2.5 的 3B / 7B 验证,超过 GRPO 与多个强自蒸馏基线,ALFWorld 上 7B 拿到 89.1% 成功率。
    为什么值得关注:Agent RL 的成本大头是采样和 critic,而这篇把两样都省了。当训练 Agent 变贵,创新的方向就从「加什么」变成「砍什么」。
    研究arXiv2026-08-08
  3. GST-Bench:看了 6790 分钟视频,顶尖视觉模型依然「不知道自己在哪」 — HF Papers 上榜(37 赞)。现有空间智能基准几乎都在测单视角或少数视角下的局部感知,没人系统检验模型能否在长视频里维持一个全局一致的场景表征。GST-Bench 用 6790 分钟合成视频 + 人工核验问题构建,要求模型从视频里根本没出现过的视角做空间推理,并把第一人称观察映射到全局俯视地图上;还配了 GST-Bench-Local 用于区分「局部看不懂」还是「全局拼不起来」。22 个前沿视觉模型参评,最好的零样本成绩仅 42.68 分,而人类是 79.08。结论明确:模型的局部空间理解其实不弱,瓶颈在于把长时间跨度的观察整合成一张连贯的地图。
    为什么值得关注:这是具身智能和机器人绕不开的一关——你可以逐帧看懂每个画面,却依然说不出「刚才那个房间在我左边还是右边」。人类 79 分 vs 模型 43 分的差距,划出了当前多模态模型最真实的一条边界。

  4. HarnessOpt-Bench:把「优化脚手架」本身当成一项模型能力来考 — 它测的是一件以前没人系统量化过的事:前沿模型有多会优化「模型周围的那一圈东西」——提示词、工具、控制流、记忆与编排代码。玩法是:给优化者模型一个目标 Agent 的种子 harness、评测反馈和固定预算,让它反复改写、最后提名一个候选版本,按在隐藏测试集上相对种子版的归一化增益计分;全程在可信执行环境里跑,计量资源、保留所有候选版本以供审计。5 个前沿模型 × 4 个下游任务 × 111 次计分运行,得出三条结论:优化者模型之间的差距,大于它们所用编码 harness 之间的差距;用「自家原生 harness」并不总是更好;收益高度依赖任务与种子版本。
    为什么值得关注:它把 prime-agent 那种「Agent 自己改自己脚手架」的能力,钉成了一个可测量的坐标。而「自家原生 harness 未必更好」这条,今天被 Floatboat 那组数字狠狠印证了一遍。

今日新词

  • Harness(脚手架 / 外壳):今天出现频率最高的词。模型本身只是个「大脑」,harness 是围在它外面的那一整套东西——提示词怎么写、能调哪些工具、多步任务怎么编排、上下文怎么压缩、记忆存在哪、失败了怎么重试。今天 Floatboat 用一组数字证明:同一位厨师,在家庭厨房和专业后厨里做出的菜,完全不是一个水平。而 HarnessOpt-Bench 更进一步,把「会不会改造后厨」也当成厨师的一项能力来考。
  • 编程式工具调用(Programmatic Tool Calling):让模型调用外部工具的两种方式。老办法是让它吐一段固定格式的 JSON(相当于填表),新办法是把工具变成 Python 函数、让模型直接写代码调(相当于给它一个终端)。今天那篇《工具调用的苦涩教训》的发现是:填表的方式在长上下文里会退化,写代码的方式则稳得多,而且模型越强差距越大。
  • 模型蒸馏(Distillation):用一个强模型(老师)的输出去训练一个小模型(学生),让学生快速学到老师的本事。好处是省钱省算力,坏处是你的上限被老师锁死了,而且用别家模型当老师还可能踩法律红线——今天张一鸣反对它,理由正是这两条。
  • RSI / 递归自我改进(Recursive Self-Improvement):让 AI 参与改进 AI 自己。今天出现了三个层次的版本:prime-agent 改的是脚手架,EverMind 攒的是技能库,BigBang-V1 最激进——连训练数据都交给 AI 生产。它成立的前提很硬:必须有个靠谱的验证器,否则自产自销就是自我催眠。
  • 两用(Dual-Use):同一份知识既能救人也能害人——研究疫苗和研究病原体用的是同一套技术。这是 AI 安全里最难切的一刀,因为你没法只靠问题本身判断提问者的意图。今天 Anthropic 放宽 Fable 5 生物护栏、把回退率砍掉 85%,做的就是把这一刀切得更细,而不是索性把整个领域都封掉。
